# KNOWLEDGE BASE SYNCHRONIZATION

Objective

Synchronize all knowledge-base documents after an architecture or business rule change.

Never update only one document.

Always review the complete knowledge base.

Review documents in this order:

1. business-context.md
2. BRD.md
3. PRD.md
4. ERD.md
5. prisma-schema.md
6. architecture.md
7. api-contract.md
8. user-stories.md
9. wireframes.md
10. sprint-plan.md
11. ai-prompt-context.md

Tasks

1.
Identify inconsistent business rules.

2.
Identify outdated modules.

3.
Identify outdated entities.

4.
Identify outdated API.

5.
Identify outdated architecture.

6.
Generate synchronization plan.

Wait approval.

After approval

Update every affected document.

Never change business logic without approval.

Output

For every document provide

• Required changes

• Reason

• Impact

• Cross reference

Finally produce

Knowledge Base Change Summary

Knowledge Base Version
