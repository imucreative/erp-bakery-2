# 42. Golden Module Checklist

This checklist defines the standard implementation steps required for every ERP business module in Bakery ERP. Every feature/module delivery must satisfy and check off these components.

## Backend Checklist

- [ ] **Prisma**: Define the database models in `prisma.schema` following normalization and ERD definitions.
- [ ] **Migration**: Generate and execute the Prisma migration (`npx prisma migrate dev --name <migration_name>`).
- [ ] **Seed**: Update `prisma/seed.ts` with idempotent, repeatable seed data for the module.
- [ ] **DTO**: Create DTO validation classes extending the base query DTOs (`BasePaginationDto`, `BaseSearchDto`, `BaseListDto` / `SupplierQueryDto` pattern).
- [ ] **Repository**: Create a repository class extending `BaseRepository` with soft-delete and search capabilities.
- [ ] **Service**: Create a service class extending `BaseCrudService` for standard CRUD logic and audit logging.
- [ ] **Master Data Protection**: For master-data modules, use the shared dependency protection standard before delete, soft-delete, or deactivation.
- [ ] **Controller**: Create a controller class extending `BaseController` using standard `ApiResponse` response formatters.
- [ ] **Swagger**: Document all endpoints using NestJS Swagger decorators (`@ApiTags`, `@ApiOperation`, `@SwaggerResponse`).
- [ ] **Permission**: Configure authorization guards and decorators using permissions (e.g. `product.read`, `procurement.pr.manage`).
- [ ] **Audit**: Implement logging using `winstonLogger.audit` with authorized actions: `CREATE`, `UPDATE`, `DELETE`, `SUBMIT`, `APPROVE`, `REJECT`, `CANCEL`, `REOPEN`, or `CLOSE`.
- [ ] **Unit Test**: Implement unit tests for services verifying custom business logic, constraints, and audit logs.
- [ ] **Integration Test**: Implement integration tests verifying endpoint access, payloads, and response formatting.

## Frontend Checklist

- [ ] **API Service**: Define API methods using `apiClient` mapping paginated response structures cleanly.
- [ ] **Query**: Create custom React Query hook wrappers using `useBaseQuery` and centralized `QueryKeys` registry.
- [ ] **Mutation**: Create custom React Query mutation wrappers using `useBaseMutation` with automated invalidations.
- [ ] **React Hook Form**: Integrate `react-hook-form` to manage form states.
- [ ] **Zod**: Integrate Zod schemas for form state validations.
- [ ] **ERP Form**: Assemble forms using `ERPFormDialog`, `ERPForm`, `ERPFormSection`, and `ERPFormActions`.
- [ ] **ERP DataTable**: Use `ERPDataTable`, `ERPTable`, `ERPTableHead`, `ERPTableBody`, `ERPTableRow`, `ERPTableCell`, `ERPTableActionCell`, and `ERPTablePagination` to present listings.
- [ ] **ERP Filter**: Set up filters using `ERPFilterBar` and `ERPSearchInput`.
- [ ] **ERP Notification**: Integrate the `notify` helper for success/error mutation feedback, reusing the shared API error extraction helper so useful backend validation messages are shown.
- [ ] **ERP Loading**: Show the skeleton screen loader `ERPLoading` when data fetching.
- [ ] **ERP Empty**: Use the empty state component `ERPEmpty` when no data matches criteria.

## Verification Checklist

- [ ] **Type Check**: Validate that typescript type checking builds without errors (`npm run build` or `npx tsc --noEmit`).
- [ ] **Build**: Run production-ready builds on backend and frontend successfully.
- [ ] **Self Review**: Verify all business and validation rules are satisfied without regressions.
- [ ] **Done**: Mark task as complete and prepare walkthrough documentation.
