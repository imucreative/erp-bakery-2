This document defines the architectural standards for structuring frontend modules in the Bakery ERP. All future modules must follow this directory layout under `frontend/src/app/(dashboard)/<module>/` to ensure consistent separation of concerns, scalability, and code reuse.

---

## Directory Layout

```text
src/app/(dashboard)/<module>/
├── page.tsx               # Entry Point: Main module view orchestrator
├── components/            # Folder: Presentation components
│   ├── header.tsx         # Module page title and main action buttons
│   ├── filter-bar.tsx     # Search and filter options
│   ├── table.tsx          # Data grid rendering
│   ├── columns.tsx        # React Table column definitions
│   ├── form-dialog.tsx    # Create and edit entity dialog forms
│   ├── delete-dialog.tsx  # Confirmation dialog for item deletions
│   └── index.ts           # Exports barrel file
├── hooks/                 # React Query queries, mutations, and local state management
├── services/              # API Client wrappers utilizing axios/fetch
├── schemas/               # Zod validation schemas (shared between forms & API clients)
├── types/                 # TypeScript interfaces and type declarations
├── constants/             # Enums, colors, routing strings, and fixed data options
└── api/                   # (Optional) Next.js route handlers if bypassing direct proxy
```

---

## Directory Responsibilities

### 1. `page.tsx`
- **Responsibility**: Module root and page orchestrator.
- **Rules**: Can perform server-side data fetching or orchestrate client-side rendering. Integrates layout components, coordinates loading states, and registers state providers. It must NOT contain inline forms or direct API request logic.

### 2. `components/`
This folder holds presentation-only components.
- `header.tsx`: Renders names and action buttons (uses `ERPPageHeader`).
- `filter-bar.tsx`: Manages local filter state changes (uses `ERPFilterBar` and `ERPSearchInput`).
- `table.tsx`: Displays lists, manages pagination, and exposes action buttons (uses `ERPDataTable`).
- `columns.tsx`: Definitive column declarations and row-action event delegation (uses `ERPStatusBadge`).
- `form-dialog.tsx`: Modals hosting data input fields (uses `ERPFormDialog` and `ERPForm`).
- `delete-dialog.tsx`: Voids or deletes items with confirmation (uses `ERPDeleteDialog`).
- **Presentation Rule**: Components under `components/` should remain as stateless and logic-free as possible. They should receive data and event handlers via React props.

### 3. `hooks/`
- **Responsibility**: Data synchronization, state management, and business logic execution.
- **Rules**: Holds React Query `useQuery` and `useMutation` wrappers that hook into the Services layer. Keeps form handling logic (`useForm`) out of components, separating React hook validations from JSX structures.

### 4. `services/`
- **Responsibility**: HTTP communication client.
- **Rules**: Interfaces NestJS endpoints. Standardizes request/response mapping and parses errors into toast notifications. Uses Axios/Fetch instances configured with global interception tokens.

### 5. `schemas/`
- **Responsibility**: Validation constraints.
- **Rules**: Hosts shared Zod schemas (e.g., `createProductSchema`) used by both `react-hook-form` inputs and services/API requests.

### 6. `types/`
- **Responsibility**: Static typing.
- **Rules**: Declares core domain TypeScript interfaces (e.g. `Product`, `VendorInvoice`) and database representation overrides.

### 7. `constants/`
- **Responsibility**: Immutable settings.
- **Rules**: Stores UI static configurations, options select arrays (e.g., Status options), and route paths.

## Separation of Concerns: Logic vs. Presentation

To maintain a clean codebase, files are categorized by whether they may contain business logic:

| Folder / File | Logic Allowed? | Description |
| --- | --- | --- |
| `page.tsx` | **NO** | Presentation orchestrator only. Composes layout components. |
| `components/*` | **NO** | Strictly UI presentation. Renders props and dispatches events. |
| `hooks/*` | **YES** | React Query queries, form state management, validations, and handlers. |
| `services/*` | **NO** | API clients only. Formats requests and receives payloads. |
| `schemas/*` | **YES** | Zod schemas containing validation assertions and constraints. |
| `types/*` | **NO** | Type declarations only. |
