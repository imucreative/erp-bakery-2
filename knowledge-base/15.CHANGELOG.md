## v1.6.0

### Added
- **Tailadmin UI foundation — `BaseAlert` & `BaseModal`** (`frontend-tailadmin/src/components/ui/`):
  - `BaseAlert.vue`: banner inline dengan `variant` (error/success/warning/info), `size`
    (sm/md), slot `icon`, `dismissible` + event `dismiss`, self-hiding saat kosong, dan
    `role="alert"`/`role="status"` otomatis.
  - `BaseModal.vue`: kerangka modal standar (backdrop transparan sesuai §2.4, panel
    `rounded-3xl` + `shadow-theme-lg`, `role="dialog"` + `aria-modal="true"`, tutup via
    klik backdrop atau Esc, ukuran `md`/`lg`/`xl`/`2xl`, opsi `scrollable`).
  - Migrasi modul: Outlets, Users (`UserFormModal`, `UserDeleteModal`), Roles
    (`RoleFormModal`, `RoleDeleteModal`, `RoleDetailModal`, `RolePermissionPicker`), POS
    terminal, dan `BaseTable`. Sisa ±33 modal dan ±55 banner dijadwalkan bertahap
    (dok 48 §2.8).

### Standardized
- **Core CSS snippet class** (dok 48 §2.8): 11 `@utility` Tailwind v4 di
  `frontend-tailadmin/src/assets/styles/ui.css` — `page-title`, `card-title`, `modal-title`,
  `text-muted`, `form-label`, `form-hint`, `form-error`, `alert-*`, `no-scrollbar`,
  `custom-scrollbar` — dipakai sebagai pengganti rantai class panjang di tiap komponen.
- **Pemisahan `main.css`** menjadi satu entry (14 baris: `@import` + `@custom-variant`) dan
  7 partial berkategori di `src/assets/styles/`: `theme.css`, `base.css`, `menu.css`,
  `ui.css`, `inputs.css`, `vendor.css`, `rtl.css`. Urutan `@import` dipertahankan sama agar
  cascade tidak berubah (dibuktikan: 389 aturan CSS hasil build identik sebelum/sesudah).
- **Pemangkasan CSS mati** dari `main.css`: 789 baris / 168 selector dihapus (blok
  FullCalendar, simplebar, Swiper carousel, code editor/prism, sidebar docs template,
  `#mapTwo`, `#mapCustomerPinPoint`, `.menu-accordion`, `.sidebar:hover`, `.tableCheckbox`,
  `.form-check-*`). Setiap selector yang dihapus lebih dulu dipastikan tidak dimiliki file
  `src/` mana pun. Penghapusan ini sekaligus menghilangkan `html.dark [role="dialog"]`
  `!important` yang mengunci warna panel modal di dark mode.
### Fixed
- **Indikator kalender native pada field tanggal** (`frontend-tailadmin/src/assets/styles/inputs.css`):
  blok template "Remove Date Icon" (`display/opacity … !important`) selama ini mengalahkan
  blok ERP sehingga ikon kalender tidak pernah muncul di form Production/Procurement/Inventory.
  Blok dihapus; field `input[type=date]` kini menampilkan ikon kalender (di-`invert` saat dark)
  dan `cursor: pointer`. Aman karena aplikasi tidak memiliki `type="time"` dan tidak ada field
  tanggal yang memasang ikon sendiri. Diverifikasi A/B lewat screenshot pada field
  "Tanggal Dibutuhkan" di form Purchase Request.

### Documentation
- Dokumentasi: `18.frontend-design-system.md` ditandai usang untuk `frontend-tailadmin/`
  dengan pointer ke dok 48 §2.0 dan §2.8.

## v1.3.0

### Added

- **Product Group Master Data Module**:
  - Introduced the new master classification level above Product Categories.
  - Defined business properties: Code (unique, uppercase), Name (unique), Description, Status (isActive), and Soft Delete (`deletedAt`).
- **Product Group API Contracts**:
  - GET `/product-groups` (paginated list, with filtering and search)
  - GET `/product-groups/lookup` (returns simplified list of active groups)
  - GET `/product-groups/:id` (returns group details)
  - POST `/product-groups` (creates a new group, requires unique code and name)
  - PUT `/product-groups/:id` (updates name/description/isActive)
  - DELETE `/product-groups/:id` (soft delete validation, checks for active references)
- **Product Group User Stories**:
  - Added stories PG-001 (Create Product Group), PG-002 (Update Product Group), and PG-003 (Deactivate/Delete Product Group).
- **Product Group Wireframe Screens**:
  - Added wireframe layouts and routes for `/masters/product-groups` (List) and `/masters/product-groups/create` (Form).

### Updated

- **Product Classification Hierarchy**:
  - Formally updated the system-wide product hierarchy in `1.business-context.md` to: `Product Group` → `Category` → `Product`.
- **Business Requirements (BRD)**:
  - Added `Product Group` to the In-Scope Master Data list in `2.BRD.md`.
  - Added functional requirements: `FR-015 Product Group Management` and updated `FR-002 Product Management` to specify references to Product Group, Category, UOM, and Supplier.
- **Product Requirements (PRD)**:
  - Added Section `5.5 Product Group Management` and updated Section `5.3 Product Management` to include `Product Group` and `Supplier` references.
  - Added acceptance criteria for validating category-group relationships.
- **Entity Relationship Diagram (ERD)**:
  - Added `product_groups` entity definition.
  - Updated `product_categories` and `products` tables with foreign keys and relationships.
  - Documented high-level relationship changes.
- **Prisma Schema Specification**:
  - Added `ProductGroup` model with relationships.
  - Updated `ProductCategory` and `Product` models with foreign key fields, relations, and indexes.
  - Standardized `Unit` model to `Uom` to match the actual database schema implementation.
- **System Architecture**:
  - Added `product-group` module to backend project structure, NestJS directories, module boundaries, and frontend features.
- **API Contracts**:
  - Updated `GET /products` filters, `POST /products` payload, and `/categories` payloads to include new foreign key fields (`productGroupId`, `supplierId`, `uomId`).
- **Sprint Plan**:
  - Integrated `Product Group` into Sprint 1 Master Data scope and adjusted the Sprint 1 Story Points to 37.
- **AI Prompt Context**:
  - Added `Product Group Management` to permanent AI context modules list.
- **Implementation Checklist**:
  - Added concrete checklist tasks for `Product Group Management` under Sprint 1 (API, UI, Validation, Tests, Audit Log).
