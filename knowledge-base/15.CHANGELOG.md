## v1.6.0

### Added
- **Tailadmin UI foundation — `BaseAlert` & `BaseModal`** (`frontend-tailadmin/src/components/ui/`):

    Toppings (`ToppingFormModal` pakai `size="xl" scrollable`, `ToppingDeleteModal` md), POS
    terminal, Purchase Request (`PurchaseRequestActionModals` md + banner load/form/action/upload

    `BaseTable`. Sisa 12 backdrop modal manual dan 48 call site banner dijadwalkan bertahap (dok 48 §2.8).

  Order: rantainya terukur 60 call site di 12 file — melewati ambang ±60 — dan dipakai 11 situs
  sekaligus di `PurchaseOrderSummary`; bedanya dengan `text-strong` hanya `font-medium` (label

- **Snippet kerangka `toolbar-row` + `confirm-bar` + `field-grid`** (dok 48 §2.8): pengecualian
  kedua untuk ambang ±60, disetujui 2026-10-24 — rantai tata letak yang bertambah satu situs tiap
  modul baru.
  `flex flex-col gap-3 sm:flex-row sm:items-center sm:justify-between` dipakai 28 situs (23 halaman
  `*List.vue`, 4 komponen `*Comments.vue`, `ShiftBar.vue`) dan kini jadi `class="toolbar-row"`; bar
  konfirmasi inline hapus-lampiran (4 situs identik di 4 komponen `*Attachments.vue`) jadi
  `class="mt-3 confirm-bar"`; kisi dua kolom `grid grid-cols-1 gap-4 sm:grid-cols-2` sebanyak 29
  situs di 27 file (semua `*HeaderFields`/`*Summary` + modal form master data) jadi
  `class="field-grid"`. Sengaja tidak disentuh: 3 situs di template demo (`views/Ecommerce.vue`,
  `components/ecommerce/EcommerceMetrics.vue`) dan kulit kartu kotak totals `PurchaseOrderSummary`
  (dok 48 §2.8 — sampai increment ini hanya kerangkanya yang menyusul, lihat catatan di bawah). Verifikasi di
  `dist/assets/index-1t8Ooov-.css`: `.toolbar-row` (offset
  16595) memancarkan `gap/flex-direction:column/display:flex` plus blok
  `@media(min-width:640px){flex-direction:row;justify-content:space-between;align-items:center}`,
  dan `.confirm-bar` (15844) memancarkan seluruh 10 deklarasi rantai lama termasuk
  `border-color:color-mix(… error-500 30%)` dan `.confirm-bar:is(.dark *){background-color:#f044381a}`
  (= `error-500/10`) — jadi perilakunya identik, termasuk titik responsif `sm` = 640px. `alert-error`
  tidak dipakai untuk bar ini (bingkainya `/40`, dan snippet itu sengaja tanpa tata letak karena
  pasangannya `BaseAlert`). Verifikasi `field-grid` di build berikutnya
  (`dist/assets/index-BqG3AD0Y.css`): dua rule, `.field-grid` di 15845
  (`display:grid; grid-template-columns:repeat(1,minmax(0,1fr)); gap:4`) dan salinannya di dalam
  `@media(min-width:640px)` pada 15969 (`repeat(2,minmax(0,1fr))`) — titik responsif sama dengan
  `sm:` yang dipakai rantai lama. Lanjutan hari yang sama, atas permintaan terpisah: kotak totals
  (Subtotal / Pajak / Grand Total) di `PurchaseOrderSummary` ikut memakai kerangka itu —
  `mt-2 grid grid-cols-1 gap-2 … sm:grid-cols-3` menjadi `mt-2 field-grid gap-2 … sm:grid-cols-3`,
  jadi situs `field-grid` ke-30 (tetap 27 file). Ini call-site pertama yang **menimpa dua properti
  milik snippet sendiri**, jadi urutannya dibuktikan lebih dulu: `.gap-2` 22564 dan
  `.sm\:grid-cols-3` 57722 keduanya muncul setelah `.field-grid` base 15845 maupun salinan
  `@media(min-width:640px)`-nya 15969, sehingga `gap:2` dan 3 kolom tetap menang dan tampilan tidak
  berubah. Ukuran CSS hasil build tetap 133.256 byte (tidak ada rule baru; `grid`/`grid-cols-1` core
  masih dipakai pemanggil lain). Kulit kartunya (`rounded-xl border border-gray-200 p-4` tanpa
  `bg-white`) sengaja tetap rantai manual — bukan `panel-card`.
  Catatan metodologi: probe selector ber-escape (`sm\:…`) harus
  memakai pencarian literal tanpa backslash ganda; pola `\\:` di string JS memberi false negative
  (pernah terjadi dua kali di increment ini). Trade-off dicatat: CSS build naik 132.364 → 133.073 →
  133.256 byte (+0.9 kB) sementara 58 rantai panjang hilang dari source (28 `toolbar-row`/`confirm-bar`
  + 30 `field-grid`).
- **Pemangkasan duplikat tombol "kembali"** (dok 48 §2.8): rantai 10-class `inline-flex h-10 w-10 …

## v1.3.0

### Added

- **Product Group Master Data Module**:
  - Introduced the new master classification level above Product Categories.
  - Defined business properties: Code (unique, uppercase), Name (unique), Description, Status (isActive), and Soft Delete (`deletedAt`).
- **Product Group API Contracts**:
  - GET `/product-groups` (paginated list, with filtering and search)
  - GET `/product-groups/lookup` (returns simplified list of active groups)
  - GET `/product-groups/:id` (returns group details)
  - POST `/product-groups` (creates a new group, requires unique code and name)
  - PUT `/product-groups/:id` (updates name/description/isActive)
  - DELETE `/product-groups/:id` (soft delete validation, checks for active references)
- **Product Group User Stories**:
  - Added stories PG-001 (Create Product Group), PG-002 (Update Product Group), and PG-003 (Deactivate/Delete Product Group).
- **Product Group Wireframe Screens**:
  - Added wireframe layouts and routes for `/masters/product-groups` (List) and `/masters/product-groups/create` (Form).

### Updated

- **Product Classification Hierarchy**:
  - Formally updated the system-wide product hierarchy in `1.business-context.md` to: `Product Group` → `Category` → `Product`.
- **Business Requirements (BRD)**:
  - Added `Product Group` to the In-Scope Master Data list in `2.BRD.md`.
  - Added functional requirements: `FR-015 Product Group Management` and updated `FR-002 Product Management` to specify references to Product Group, Category, UOM, and Supplier.
- **Product Requirements (PRD)**:
  - Added Section `5.5 Product Group Management` and updated Section `5.3 Product Management` to include `Product Group` and `Supplier` references.
  - Added acceptance criteria for validating category-group relationships.
- **Entity Relationship Diagram (ERD)**:
  - Added `product_groups` entity definition.
  - Updated `product_categories` and `products` tables with foreign keys and relationships.
  - Documented high-level relationship changes.
- **Prisma Schema Specification**:
  - Added `ProductGroup` model with relationships.
  - Updated `ProductCategory` and `Product` models with foreign key fields, relations, and indexes.
  - Standardized `Unit` model to `Uom` to match the actual database schema implementation.
- **System Architecture**:
  - Added `product-group` module to backend project structure, NestJS directories, module boundaries, and frontend features.
- **API Contracts**:
  - Updated `GET /products` filters, `POST /products` payload, and `/categories` payloads to include new foreign key fields (`productGroupId`, `supplierId`, `uomId`).
- **Sprint Plan**:
  - Integrated `Product Group` into Sprint 1 Master Data scope and adjusted the Sprint 1 Story Points to 37.
