# 54. ADR — `frontend-tailadmin/` sebagai Frontend Kanonik (Deprecasi `frontend/`)

**Status:** ACCEPTED
**Date:** 2026-10-05
**Deciders:** User / Project Lead, Project Manager
**Prasyarat:** ADR 45 (frontend Vue 3 migration — membangun `frontend/`), ADR 47 (TailAdmin sebagai frontend kedua)
**Supersedes:** ADR 47 §2.1 & §4 ("This ADR does NOT deprecate `frontend/`"); ADR 45 insofar as it governs the canonical frontend
**Related:** 8 (api-contract), 16 (role-permission-matrix), 18 (frontend-design-system), 24 (ai-operating-system), 35 (global-erp-standards), 48 (TailAdmin frontend backlog & UI standards), 14 (PROJECT-STATUS)

## 1. Konteks

Sejak 2026-09-28 repo ini punya **dua project frontend**:

| Folder | Asal | Kondisi nyata per 2026-10-05 |
|---|---|---|
| `frontend/` | ADR 45 — Vue 3 + Vite + **custom ERP UI Foundation** (Reka UI, TanStack Query for Vue, VeeValidate, Pinia) | **84 file ter-track. Commit terakhir `f52f92b` (2026-09-29)** — 6 hari tanpa disentuh. Isi hanya: Auth, Roles (read-only), Users (CRUD), Companies (profil read-only), 2 dashboard statis. **±4 modul dari ~15 domain.** |
| `frontend-tailadmin/` | ADR 47 — adopsi **template TailAdmin v2.4.0** (Vue 3.5 + Vite 6 + Tailwind v4) | **488 file ter-track. Commit terakhir `d651e31` (2026-10-04).** 49 view, 26 service, 32 composable — **semua domain aktif** (Master Data, Procurement, Inventory, Production, POS/Sales, System). |

Selama 6 hari terakhir **seluruh** development frontend (sesuai `project-context/2026-09-29.md` s/d `2026-10-04.md`) terjadi di `frontend-tailadmin/`. `frontend/` ditinggalkan begitu ADR 47 diadopsi.

Masalah yang muncul:

1. **ADR 47 tidak pernah menutup kondisi `frontend/`.** ADR 47 §4 secara eksplisit menyatakan *"This ADR does NOT deprecate `frontend/`"* dan menyebut TailAdmin sebagai *"an exploratory UI direction, not yet a replacement"*. Akibatnya tidak ada sumber kebenaran tunggal tentang frontend mana yang aktif.
2. **Premis "frontend masih greenfield/profiling" sudah usang.** Stack frontend sudah final dan implementasinya sudah luas, tetapi beberapa dokumen inti masih dibaca agent baru seolah stack belum diputuskan.
3. **Dokumen inti menyodorkan `frontend/` sebagai frontend aktif.** Doc 19, 23, 31, 36, 42, 13, dan doc 24 §4.A semuanya menunjuk `frontend/src/app/(dashboard)/<feature>` + `frontend/src/components/erp` (Next.js/React). Doc 24 §4.B memerintahkan *"assume all specs are correct"* — sehingga agent baru akan diarahkan ke folder yang sudah deprecated.
4. **Dua frontend = dua standar UI yang saling bertentangan** (ERP UI Foundation doc 19/45 vs UI Standards doc 48 §2). Keduanya tidak boleh berjalan berdampingan sebagai peer.

## 2. Keputusan

### 2.1 `frontend-tailadmin/` = SATU-SATUNYA frontend kanonik

`frontend-tailadmin/` adalah **frontend kanonik** project Bakery ERP. Seluruh pekerjaan frontend baru, perbaikan, dan review kode berada di folder ini. Dokumentasi, Implementation Plan, dan delegasi ke `frontend-dev` **WAJIB** merujuk ke `frontend-tailadmin/`.

### 2.2 `frontend/` = DEPRECATED

Folder `frontend/` (bespoke ERP UI Foundation, ADR 45) **DIDEPRECASI** dan:

- **TIDAK lagi dipakai** sebagai basis kerja.
- **TIDAK boleh** dirujuk sebagai sumber kebenaran, pola, atau contoh arsitektur.
- **TIDAK ada** pekerjaan baru, patch, atau build di sana. Bila ada kebutuhan di sana, atau ada blocker/ketergantungan ke sana → **STOP dan tanyakan user**; jangan menulis ke `frontend/`.
- **Tidak dihapus** (dibiarkan ter-track di repo) agar tidak menghapus riwayat dan tetap membuka ruang rollback bila sewaktu-waktu diperlukan. Penghapusan fisik adalah keputusan terpisah (butuh persetujuan user eksplisit).

> **Penting:** keputusan ini **mencabut premis** bahwa kedua frontend hidup berdampingan dan masih mungkin salah satu dipilih. Pernyataan ADR 47 §4 ("This ADR does NOT deprecate `frontend/`") hereby **superseded** oleh ADR ini.

### 2.4 Pola yang menggantikan standar React / ERP UI Foundation

| Area | Standar lama (superseded) | Standar kanonik sekarang (`frontend-tailadmin/`) |
|---|---|---|
| Orkestrasi state | React Query hooks | `composables/use<X>.ts` (plain refs + computed) |
| Fetching | React Query cache keys | `services/<x>.service.ts` (Axios + header docstring kontrak backend) |
| Form | React Hook Form + Zod | Validasi Zod di service-layer atau validasi inline di form |
| Routing | Next.js App Router `page.tsx` | `src/router/index.ts` config-based + guard `meta.permission` |
| Layout | `components/erp` foundation | Komponen TailAdmin (`src/components/ui/*`) + komponen fitur stateless di `components/<area>/<x>/` |
| View | `page.tsx` | `views/<Area>/<X>{List,Form,Detail}.vue` tipis (pemilik state) |

Detail & pengecualian wajib dibaca di **doc 48 §2** — dokumen itu sudah menggantikan peran "frontend design standard" bersama `AGENTS.md`.

## 3. Alasan

1. **Keputusan user** — user menetapkan pada 2026-10-05 bahwa `frontend-tailadmin/` adalah folder yang dipakai dan `frontend/` deprecated. Keputusan ini final, tidak untuk dibuka ulang.
2. **Bukti empiris** — 6 hari berturut-turut seluruh development frontend (Inventory 4 modul, Production 2, POS/Sales 4, Procurement 4 dokumen, Topping global, UOM conversion UI) dibangun di `frontend-tailadmin/`. `frontend/` nol perubahan sejak 2026-09-29.
3. **Cakupan & efisiensi** — `frontend/` hanya menyelesaikan ±4 modul dari ~15 domain; `frontend-tailadmin/` telah menutup hampir semuanya dengan pola UI konsisten (doc 48 §2).
4. **Tidak membuang kerja** — ADR 47 sejak awal sengaja menghindari pembuangan kerja yang sudah terbukti; keputusan ini melanjutkan argumen yang sama sampai ujungnya, dan menetapkan satu arah yang jelas.

## 4. Konsekuensi

### Positif

- Satu sumber kebenaran frontend → agent & sub-agent tidak lagi menebak.
- Standar UI tunggal (doc 48 §2) → konsisten lintas modul.
- Tidak ada lagi duplikasi dokumentasi antar dua project frontend.
- Basis kerja `frontend/` (ADR 45) tetap tersedia sebagai referensi historis di repo.

### Negatif / Risiko

- **Investasi di `frontend/` (84 file, ±4 modul) menjadi write-off.** Diterima secara sadar — nilainya historis, bukan operasional.
- **Dokumen inti masih banyak yang stale.** Status SUPERSEDED hanya berarti "jangan dipakai sebagai basis kerja", **BUKAN** "sudah diperbaiki". Daftar dokumen yang masih stale & berpotensi menyesatkan agent baru: `20.backend-constitution.md` (masih mewajibkan Prisma), `5.prisma-schema.md`, `4.ERD.md`, `13.implementation-checklist.md`, `15.CHANGELOG.md`, `32.module-development-workflow.md`. **Perbaikan dokumen-dokumen ini adalah pekerjaan terpisah dan BELUM dikerjakan.**
- **Jalur database backend belum diuji terhadap DB nyata** — test repository masih berbasis mock `pg` (lihat `53.issue-backlog.md` dan context 2026-10-03/2026-10-04). Tidak terkait langsung ADR ini, tapi relevan terhadap kepercayaan terhadap stack kanonik.

### Netral / Tidak Berubah

- Backend, skema DB, migrasi, permission, dan kontrak API **tidak berubah** sama sekali oleh ADR ini.
- Migrasi DB tetap monotonik append-only di `backend/migrations/`.
- **Tidak ada perubahan kode produksi** untuk mengimplementasikan ADR ini (dokumentasi-saja).

## 6. Tindak Lanjut (di luar cakupan ADR ini)

Tidak dikerjakan di sesi pembuatan ADR ini — perlu persetujuan/pemetaan lebih lanjut:

1. Menghapus folder `frontend/` secara fisik (butuh persetujuan user terpisah).
2. Menulis ulang dokumen inti agar sesuai stack kanonik (doc 20 Prisma → raw SQL `pg` + node-pg-migrate, doc 5, doc 4, doc 13, doc 32; refresh doc 46 & doc 48 yang alasan "ditunda"-nya sudah terpenuhi).
3. Formalisasi constitution frontend baru yang menggantikan doc 19 (draft implisit sudah ada di doc 48 §2).
