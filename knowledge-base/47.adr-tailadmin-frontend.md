> This ADR records a deliberate decision to trial a **second, separate frontend
> project** based on the TailAdmin Vue admin template, WITHOUT touching or
> replacing the existing `frontend/` app. It is an exploratory UI direction, not
> yet a replacement.

---

## 1. Context

The existing `frontend/` app (Vue 3 + custom ERP UI Foundation, governed by ADR
doc 45 + constitution doc 19) is working and verified (auth, dashboard shell,
Roles/Users/Companies modules — all built & tested). However, the User wants a
more polished, ready-made admin look and chose to adopt **TailAdmin**
(vue-tailwind-admin-dashboard v2.4.0).

To avoid discarding proven work and to de-risk the trial, the decision is to
build TailAdmin as a **separate project folder** rather than modifying the
current frontend.

## 2. Decision

### 2.1 Separate project
- New folder: `frontend-tailadmin/` (TailAdmin v2.4.0, already cloned by User).
- The existing `frontend/` app is **left untouched and keeps running** (dev port 5173).
- `frontend-tailadmin/` runs on a **different dev port (5174)** to avoid clashes.

### 2.2 Governance exemption (for this project only)
- For `frontend-tailadmin/`, the frontend constitution and ERP UI Foundation
  rules are **explicitly waived**: docs **19, 23, 37, 38** and the custom
  `components/erp` foundation do NOT bind this project. The User directed us to
  "focus on the ready-made template" instead of the bespoke foundation.
- Still authoritative (they are backend/domain contracts, not UI style): doc **8**
  (api-contract, corrected by doc 45 §4), doc **16** (role-permission-matrix),
  and the SaaS tenant rules — these apply IF/WHEN this project integrates with
  the real backend (Phase 2).

### 2.3 Stack (from TailAdmin package.json v2.4.0)
Vue 3.5 + Vite 6 + TypeScript + **Tailwind CSS v4** + Vue Router 4. UI libs:
ApexCharts, FullCalendar, flatpickr, leaflet/jsvectormap, dropzone, swiper,
floating-vue, vuedraggable, lucide-vue-next. All open-source (MIT-compatible).
Note: TailAdmin uses Tailwind v4; the existing `frontend/` uses v3.4 — isolated
because the projects are separate.

### 2.4 License
TailAdmin free v2.4.0 is **MIT** (see `frontend-tailadmin/LICENSE`). Free to use,
modify, and distribute provided the copyright + permission notice is retained.
Any paid/pro TailAdmin components are NOT used; where a needed component is
pro-only, replace with an open-source equivalent or build it in-house.

## 3. Phased Plan

- **Phase 1 (this ADR's immediate scope):** install dependencies, ensure
  type-check + build are green, and run the dev server so the template renders
  with its built-in DUMMY data. No backend integration, no code changes to the
  template beyond what's needed to run.
- **Phase 2 (future, separate approval):** integrate with the real backend —
  auth (`POST /auth/login`, JWT decode, `/companies/me`), then replace dummy
  pages with real modules (Users/Roles/Companies) following TailAdmin's styling.
  Phase 2 must honor docs 8 & 16 and the tenant rules.

## 4. Consequences

- Two frontend projects coexist: `frontend/` (bespoke, governed by doc 45/19) and
  `frontend-tailadmin/` (template-based, governed by this ADR).
- A future decision may promote one as the canonical frontend; until then both
  are kept. This ADR does NOT deprecate `frontend/`.
- Backend, permissions, and API contracts are unchanged by this ADR.
- The context-logger rule still applies: work on `frontend-tailadmin/` is logged
  in `knowledge-base/project-context/`.
