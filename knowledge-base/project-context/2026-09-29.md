## [08:17] Investigasi runtime E2E bug "menu/tombol kadang tidak bisa diklik" — Kiro (qa-engineer)

User (via project-manager) melaporkan bug interaksi UI frontend (Vue 3 + Vite + reka-ui 2.0.0): menu/tombol "kadang bisa kadang tidak" diklik, TANPA error di console, intermiten. Saya diminta menjalankan aplikasi nyata (punya akses shell) dan menguji 3 hipotesis. Saya READ-ONLY terhadap kode produksi — hanya melaporkan.

Setup: PostgreSQL live di localhost:5435 (erp_bakery, 28 tabel sudah termigrasi). Backend `npm run start:dev` jalan di :3000. Frontend `npm run dev` jalan di :5173. Untuk uji runtime DOM saya install puppeteer sementara (`--no-save`, tidak mengubah package.json) + Chrome cache, lalu drive browser headless login sebagai owner@bakery.test.

TEMUAN UTAMA:

1) HIPOTESIS #1 (reka-ui Dialog body pointer-events leak) — **TERBUKTI, PENYEBAB UTAMA.**
   - Trigger presisi: NAVIGASI (klik RouterLink/menu nav) SAAT modal reka-ui masih terbuka (mis. buka "Add user" di Users lalu klik menu Owner Dashboard/Roles). Ini meng-unmount DialogRoot tanpa proses close normal.
   - Mekanisme: `DialogContentModal` reka-ui hardcode `disable-outside-pointer-events: true`; `DismissableLayer.js` (baris 77-78) menyetel `document.body.style.pointerEvents="none"` saat layer open dan seharusnya memulihkannya di cleanup watchEffect. Saat route berganti meng-unmount dialog, cleanup restore TIDAK berjalan benar → `body { pointer-events:none }` tersisa + `DialogOverlay` (`fixed inset-0 z-50 bg-black/50 backdrop-blur-sm`) tertinggal di DOM.
   - Bukti runtime: 3/3 iterasi → body inline & computed `pointer-events:none`, 1 `[role=dialog]` + 1 overlay `fixed inset-0` tersisa, klik nav = `BLOCKED:DIV`, TIDAK pulih sendiri (tetap sama setelah tunggu 1.5s), tanpa error console relevan. Cocok persis dgn gejala.
   - Close normal (Escape / tombol Cancel) memulihkan dgn benar (body kembali `auto`, nav CLICKABLE).
   - Lokasi: frontend/src/components/ui/PrimitiveModal.vue (DialogRoot/DialogPortal/DialogContent, overlay baris 43-45); dipakai oleh ERPFormDialog/ERPDeleteDialog → UsersFormDialog/UsersDeleteDialog. reka-ui: node_modules/reka-ui/dist/DismissableLayer/DismissableLayer.js:77-85 & Dialog/DialogContentModal.js:27.

2) HIPOTESIS #2 (toast host menutupi area klik) — **TERBUKTI, PENYEBAB SEKUNDER (transien).**
   - Saat toast aktif (mis. "Signed in" setelah login), kotak toast desktop berada di top-4 kanan (top:16 bottom:84, left:872 right:1256) dengan `pointer-events:auto`. Tombol topbar "Switch to light/dark mode" (pusat ~1133,32) & "Logout" (~1208,32) berada DI DALAM area toast → `elementFromPoint` mengembalikan teks toast (`P.text-sm`), `blocked:true` selama toast tampil.
   - Setelah toast hilang (auto-dismiss 4.5s), tombol kembali `blocked:false` / CLICKABLE. Sifat self-heal 4.5s inilah yang membuat gejala terasa "intermiten".
   - Lokasi: frontend/src/components/erp/ERPNotification.vue:32 (`pointer-events-auto`), :30 (container `sm:items-end` top-4 z-50); durasi frontend/src/stores/notification.ts:19 (`DEFAULT_TIMEOUT_MS=4500`). Topbar header z-20 < toast z-50.

3) HIPOTESIS #3 (router guard menolak permission diam-diam) — **TIDAK TERBUKTI untuk OWNER.**
   - DB: owner@bakery.test = role OWNER, is_super_admin=false, aktif, 105 permission termasuk dashboard.read/user.read/role.read. Login API 200; JWT claim `permissions` = 105 termasuk ketiga permission tsb. Guard `hasPermission` LOLOS untuk semua route ter-gate. Bukan penyebab gejala OWNER.
   - CATATAN LATEN (risiko sekunder): guard di router/index.ts:99-101 mengarahkan permission gagal ke `dashboard-owner`, padahal `dashboard-owner` sendiri butuh `dashboard.read`. Role yang TIDAK punya dashboard.read (mis. KASIR/PRODUKSI per seed) akan loop/abort saat redirect home `/` → dashboard-owner dan pada route yang ditolak → tampak "klik tidak berfungsi" tanpa error. Perlu diperbaiki agar redirect fallback aman.

Catatan tambahan (code quality): terlihat warning console reka-ui "<SelectItem /> must have a value prop that is not an empty string" (kandidat: Select dengan value string kosong di filter/opsi Users) dan sekali "Cannot read properties of null (reading type)". Bukan penyebab utama, tapi layak dibersihkan.

VERDICT: **NOT DONE** — modul interaksi UI punya 2 bug terkonfirmasi (H1 primer persisten, H2 sekunder transien) + 1 risiko laten guard. Perbaikan didelegasikan ke frontend-dev.

- File yang dibuat/diubah: TIDAK ADA kode produksi diubah (QA read-only). File konteks ini dibuat.
- Hasil verifikasi: DB connect OK (28 tabel); login owner 200 + JWT 105 permission; puppeteer 3/3 reproduksi H1; pengukuran geometri H2 desktop 1280 membuktikan overlap topbar. Workspace git bersih (puppeteer --no-save, artefak .qa-tmp dihapus).
- Rekomendasi perbaikan (untuk frontend-dev):
  - H1: pastikan modal/drawer ter-close SEBELUM navigasi, atau reset paksa `document.body.style.pointerEvents` + bersihkan portal saat unmount. Opsi: (a) di DashboardLayout, tutup semua dialog sebelum RouterLink navigate; (b) tambahkan global `router.afterEach` yang menutup dialog & me-reset body pointer-events; (c) audit versi/patch reka-ui atau bungkus DialogRoot agar `@update:open(false)` dipanggil saat unmount.   - H3 (laten): ubah fallback guard agar tidak me-redirect ke route yang butuh permission yang mungkin tidak dimiliki; arahkan ke route aman universal atau ke halaman "no access". Lokasi: router/index.ts:99-101 (+ home redirect :36).
- Langkah berikutnya: project-manager mendelegasikan H1 & H2 (dan opsional H3 laten + warning SelectItem) ke frontend-dev; setelah diperbaiki, QA re-run gate terkait (reproduksi H1 harus 0/ N, overlap H2 hilang) sebelum verdict naik ke DONE.

## [09:05] Perbaikan 3 bug interaksi UI (H1/H2/H3) + warning SelectItem — Kiro (frontend-dev)

Project-manager mendelegasikan perbaikan atas 3 bug yang dikonfirmasi qa-engineer di entri [08:17]. Sebelum menulis kode saya baca laporan QA + semua file terkait (router, PrimitiveModal/PrimitiveDialog, ERPNotification, DashboardLayout, PrimitiveSelect, ERPSelect, UsersFilterBar, UsersView). Semua fix menjaga arsitektur lapisan doc 19 (primitive tetap di components/ui), tanpa mengubah kontrak API/permission/routing backend, tanpa placeholder.

BUG #1 (HIGH — body pointer-events leak saat dialog di-unmount karena navigasi). Diperbaiki berlapis (defense in depth):
- (a) Safety net global: `router.afterEach` me-reset `document.body.style.pointerEvents = ''` setelah SETIAP navigasi, sehingga app tidak pernah stuck meski cleanup reka-ui terlewat.
- (c) Cleanup komponen: `PrimitiveModal.vue` & `PrimitiveDialog.vue` menambahkan `onBeforeUnmount` yang (1) meng-emit `update:open(false)` bila masih open agar parent state ikut reset, dan (2) memulihkan `document.body.style.pointerEvents = ''`. Perilaku close normal (Escape/Cancel/overlay-click) tidak diubah — hanya menambah jaring pengaman saat unmount.

BUG #2 (MEDIUM — toast menutupi tombol topbar). Container toast di `ERPNotification.vue` dipindah dari `top-4` (menimpa header z-20 selama 4.5s) ke `bottom-4` (mobile: tengah bawah; desktop `sm:right-6` pojok kanan-bawah). Container tetap `pointer-events-none`, kartu tetap `pointer-events-auto`. Arah animasi transisi dibalik (translateY +6px) agar slide-up dari bawah terasa natural. Tidak lagi overlap tombol theme/logout, tetap terlihat baik light/dark & mobile/desktop.

BUG #3 (LATEN — fallback redirect ke dashboard-owner yang butuh dashboard.read → potensi loop untuk KASIR/PRODUKSI). Di `router/index.ts`:
- Tambah route virtual `landing` (tanpa meta.permission) + fungsi `resolveSafeLanding()` yang memilih tujuan pertama yang benar-benar boleh diakses user dari daftar kandidat berurutan (dashboard-owner → users → roles → company), dengan `company` sebagai fallback universal (tanpa gate) sehingga TIDAK mungkin loop.
- Home `/` sekarang redirect ke `landing` (bukan langsung dashboard-owner). Guard permission-denied dan redirect login→home juga memakai `resolveSafeLanding()`.

OPSIONAL (warning reka-ui `<SelectItem/> value tidak boleh empty string`). Diperbaiki di lapisan ui `PrimitiveSelect.vue`: opsi ber-value `''` (opsi "All roles"/"All statuses") dipetakan ke sentinel internal `__erp_empty__` khusus untuk reka-ui SelectItem, lalu diterjemahkan balik ke `''` saat emit. Kontrak publik ERPSelect/filter TIDAK berubah: `modelValue` & nilai emit tetap `''` = no selection, sehingga `roleId=''`/`isActive=''` → `undefined` saat kirim ke API tetap benar (dicek di UsersView).

- File yang diubah: `frontend/src/router/index.ts`, `frontend/src/components/ui/PrimitiveModal.vue`, `frontend/src/components/ui/PrimitiveDialog.vue`, `frontend/src/components/erp/ERPNotification.vue`, `frontend/src/components/ui/PrimitiveSelect.vue`.
- Hasil verifikasi: `npx vue-tsc --noEmit` bersih (0 error); `npm run build` sukses (built in ~10s, 2281 modules).
- Keputusan penting: pendekatan berlapis untuk H1 (safety net router + cleanup unmount) agar robust terhadap semua jalur unmount. H3 memakai resolver berurutan dengan fallback `company` ungated untuk mencegah loop. Warning SelectItem ditangani di satu tempat (PrimitiveSelect) tanpa menyentuh kontrak filter.
- Langkah berikutnya: perlu QA re-run (qa-engineer) untuk verifikasi runtime — reproduksi H1 harus 0/N (body pulih, tidak ada overlay tertinggal), H2 overlap topbar hilang, H3 tidak loop untuk role tanpa dashboard.read, dan warning SelectItem hilang di console.
