## [--:--] UOM ditambahkan ke kolom laporan (Inventory, Sales, Production)

User meminta kolom UOM pada tabel laporan. Sebelumnya row laporan tidak membawa data
UOM, sehingga perubahan tidak cukup di sisi Vue.

- **Inventory Report** — `InventoryReportProductRow` + `uomCode`/`uomName` (entity,
  repository, tipe FE), kolom UOM di `InventoryReport.vue` tepat setelah *Available Qty*.
  Query memakai scalar subquery ke `uoms` lewat `products.uom_id` agar `GROUP BY`
  agregasi batch tidak berubah.
- **Sales Report (Top Selling Products)** — `SalesReportTopProduct` + UOM. `sales_order_items`
  tidak punya kolom UOM, jadi dipakai satuan dasar produk (`products.uom_id`); query
  menambah `LEFT JOIN products` + `LEFT JOIN uoms`.
- **Production Report (Daily Breakdown)** — `ProductionReportDailyBreakdown` + UOM dari
  `recipes.yield_uom_id` (`LEFT JOIN uoms`), kolom UOM setelah *Recipe*.

Nilai yang ditampilkan: `uomCode || uomName || '—'`.

Verifikasi: `tsc --noEmit` (BE) 0; `npm run build` (FE) sukses; kedua query SQL diuji
langsung ke DB dan mengembalikan UOM terisi.

File yang diubah:

- `backend/src/Domains/reports/entities/{InventoryReport,SalesReport,ProductionReport}.ts`
- `backend/src/Infrastructures/repository/ReportsRepositoryPostgres.ts`
- `frontend-tailadmin/src/services/reports.service.ts`
- `frontend-tailadmin/src/views/Reports/{InventoryReport,SalesReport,ProductionReport}.vue`

## [--:--] Perbaikan login: redirect ke route yang tidak ada

User melaporkan "tidak bisa login" sebagai `admin@erp.local`. Investigasi:

- Kredensial benar (`backend/.env` → `SUPER_ADMIN_PASSWORD=12345678`), diverifikasi dengan
  `bcrypt.compare` terhadap hash di DB → MATCH.
- `POST /api/v1/auth/login` → 200 (langsung ke backend maupun lewat proxy Vite).

Akar masalah: `Signin.vue` melakukan `router.push({ name: 'Ecommerce' })` setelah login,
padahal route bernama `Ecommerce` **tidak ada** di project ini (sisa template TailAdmin).
Push gagal → navigasi batal → user tetap di halaman signin, dan `catch` menampilkan pesan
"check your credentials" (menyesatkan).

Perbaikan:

- `Signin.vue` → redirect `{ name: 'DashboardOwner' }`.
- Redirect ini kemudian dibuat kondisional: Super Admin diarahkan ke `PlatformCompanies`
  (lihat entri Platform Console di bawah).

File yang diubah:

- `frontend-tailadmin/src/views/Auth/Signin.vue`

## [--:--] Platform Console untuk Super Admin (Opsi A) — v1

User ingin mulai masuk ke level Super Admin (`users.is_super_admin`). Desain disetujui
(lihat `knowledge-base/55.platform-console-design.md` yang dibuat pada entri ini) dengan
ruang lingkup **Opsi A**: platform console terpisah dari ERP tenant, tanpa impersonation.

Backend:

- `@SuperAdminOnly()` (`decorators/super-admin-only.decorator.ts`) ditegakkan oleh
  `PermissionsGuard` — route platform tidak memakai permission code, tetapi mensyaratkan
  `isSuperAdmin` (selain itu 403).
- `CompanyRepository` + Postgres: `listCompanies()` (search name/code/slug, `userCount`,
  pagination) dan `setCompanyActive()`.
- Endpoint baru: `GET /companies` (SUPER_ADMIN) dan `PATCH /companies/:id/status`.
- Bounded context baru `platform`: `Domains/platform/PlatformRepository.ts`,
  `Infrastructures/repository/PlatformRepositoryPostgres.ts`, `PlatformModule`, dan
  endpoint `GET /platform/users` (lintas perusahaan, join companies + roles, filter
  `companyId`, search nama/email, pagination). **Read-only** — sesuai keputusan bahwa
  Super Admin read-only terhadap data tenant.
- Registrasi DI di `InfrastructureModule` + `PlatformModule` di `app.module.ts`.

Frontend:

- `services/company.service.ts`, `services/platform.service.ts`.
- `views/Platform/CompanyList.vue` (tabel tenant + Suspend/Activate) dan
  `views/Platform/UserList.vue` (user lintas perusahaan + filter company).
- `router/index.ts`: `meta.platform`, route `/platform/companies` & `/platform/users`;
  guard: route platform hanya Super Admin; Super Admin dipaksa tetap di area platform.
- `Signin.vue`: Super Admin → `/platform/companies`.
- `sidebar/data.ts` + `AppSidebar.vue`: grup menu **Platform** khusus Super Admin
  (Companies, Users); menu ERP disembunyikan.

Keputusan yang dicatat:

- **Super Admin read-only terhadap data operasional tenant** (disetujui User). Administrasi
  identitas (user/role) tetap domain Super Admin per doc 16, tetapi penulisan lintas tenant
  belum diimplementasikan dan kelak wajib lewat `/platform/*` + audit log.
- **2FA** disetujui sebagai persyaratan untuk akun Super Admin; implementasi menyusul
  (rencana TOTP + recovery codes + alur `mfaRequired`/`mfaToken` ada di doc 55 §3.3).

Verifikasi:

- `npx tsc --noEmit` (BE) → 0; `jest src/Applications/use_case/auth src/Domains/companies`
  → 44 tests PASS.
- `npm run build` (FE) → sukses.
- API live: `GET /companies` Super Admin → 200 + meta; tanpa token → 401; token non-Super-Admin
  (di-mint untuk uji) → **403**; `PATCH /companies/:id/status` → 200;
  `GET /platform/users` → 200 dan filter `companyId` bekerja.
