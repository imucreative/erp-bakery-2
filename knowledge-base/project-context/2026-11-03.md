## [--:--] UOM ditambahkan ke kolom laporan (Inventory, Sales, Production)

User meminta kolom UOM pada tabel laporan. Sebelumnya row laporan tidak membawa data
UOM, sehingga perubahan tidak cukup di sisi Vue.

- **Inventory Report** — `InventoryReportProductRow` + `uomCode`/`uomName` (entity,
  repository, tipe FE), kolom UOM di `InventoryReport.vue` tepat setelah *Available Qty*.
  Query memakai scalar subquery ke `uoms` lewat `products.uom_id` agar `GROUP BY`
  agregasi batch tidak berubah.
- **Sales Report (Top Selling Products)** — `SalesReportTopProduct` + UOM. `sales_order_items`
  tidak punya kolom UOM, jadi dipakai satuan dasar produk (`products.uom_id`); query
  menambah `LEFT JOIN products` + `LEFT JOIN uoms`.
- **Production Report (Daily Breakdown)** — `ProductionReportDailyBreakdown` + UOM dari
  `recipes.yield_uom_id` (`LEFT JOIN uoms`), kolom UOM setelah *Recipe*.

Nilai yang ditampilkan: `uomCode || uomName || '—'`.

## [--:--] 2FA (TOTP) untuk Super Admin — v1

Implementasi persyaratan 2FA (doc 55 §3.3): backend + frontend.

Primitive keamanan (tanpa dependency baru):
- `RfcTotp` — TOTP RFC 6238 (HMAC-SHA1, 6 digit, periode 30s, toleransi ±1 langkah)
  dibangun di atas `node:crypto`; diuji memakai vektor resmi RFC 6238.
- `AesGcmSecretCipher` — AES-256-GCM untuk menyimpan secret TOTP; kunci dari
  `TOTP_ENCRYPTION_KEY` (64 hex char) yang ditambahkan ke `.env` dan `.env.example`.

Data & alur:
- Migration `1700000000072_add-users-two-factor`: kolom `two_factor_secret`,
  `two_factor_enabled`, `two_factor_recovery_codes`, `two_factor_confirmed_at`
  (sudah dijalankan ke dev DB).
- `UserRepository` + `UserRepositoryPostgres`: `getTwoFactorStateByEmail/ById`,
  `saveTwoFactorSetup`, `updateRecoveryCodes`, `setTwoFactorEnabled`.
- `TokenManager`: `createMfaToken` / `verifyMfaToken` (purpose `mfa`, 5 menit,
  secret `MFA_TOKEN_SECRET ?? ACCESS_TOKEN_SECRET`) — token ini tidak bisa dipakai
  sebagai access token.
- Use case baru (`TwoFactorUseCases.ts`): setup (secret + 10 recovery code sekali-pakai),
  enable, disable, verify-login.
- `LoginUseCase` kini mengembalikan union `{ mfaRequired: true, mfaToken }` atau
  `{ mfaRequired: false, accessToken, refreshToken }` — token TIDAK diterbitkan
  sebelum faktor kedua lolos.

Endpoint baru (`/api/v1/auth`): `POST mfa/verify`, `GET 2fa/status`, `POST 2fa/setup`,
`POST 2fa/enable`, `POST 2fa/disable`.

Frontend:
- `auth.service.ts`: `LoginResult` union + `verifyMfa` + endpoint 2FA.
- `stores/auth.ts`: `login()` mengembalikan outcome MFA (sesi belum disimpan);
  `verifyMfa()` menyimpan sesi.
- `Signin.vue`: langkah kedua (input kode TOTP/recovery) sebelum redirect.
- `components/profile/TwoFactorCard.vue` (baru) dipasang di `UserProfile.vue`.

Verifikasi:
- `tsc --noEmit` (BE) 0; `jest src/Applications/use_case/auth src/Infrastructures/security`
  → 52 test PASS (termasuk vektor RFC 6238 + cipher).
- `npm run build` (FE) sukses.
- E2E API: login → setup → enable → login `mfaRequired=true` → `mfa/verify` (TOTP) →
  200; recovery code → 200; disable → login kembali `mfaRequired=false`.
  Akun ditinggalkan dalam keadaan **2FA nonaktif** agar tidak terkunci.

Dokumentasi: `55.platform-console-design.md` §3.3 diperbarui (status v1 selesai).

## [--:--] 2FA: enforcement Super Admin + rate limit

Menindaklanjuti rekomendasi: konsol platform tidak lagi bisa diakses tanpa 2FA, dan
endpoint kredensial dilindungi rate limit.

- `PermissionsGuard` (kini async) untuk route `@SuperAdminOnly()` membaca state 2FA dari
  DB dan menolak dengan `403 AUTHORIZATION.MFA_REQUIRED` bila belum aktif. Endpoint
  enroll `/auth/2fa/*` sengaja tidak di-gate.
- `TooManyRequestsError` (429) + `InMemoryRateLimiter` (fixed window, per proses):
  `POST /auth/login` 10/menit per IP, `POST /auth/mfa/verify` 5/menit per IP
  (counter di-reset saat verifikasi berhasil).
- Frontend: `lib/twoFactorGate.ts` (cache per page load) dipakai router guard — Super
  Admin tanpa 2FA diarahkan ke `/profile?twoFactor=required`; kartu 2FA menampilkan
  notifikasi dan me-reset cache setelah enable/disable.

Verifikasi: tsc 0; `jest security + auth + companies` **78 test PASS**; build FE sukses;
E2E: tanpa 2FA `GET /companies` → 403, setelah enable → 200, login 2 langkah OK, disable
mengembalikan alur normal, dan 6 percobaan kode salah → 401×5 lalu **429**.

Catatan operasional: server dev backend sempat mati karena `SecretCipher` membaca
`TOTP_ENCRYPTION_KEY` saat startup dan env tersebut baru ditambahkan; sudah
di-restart dan berjalan normal.
