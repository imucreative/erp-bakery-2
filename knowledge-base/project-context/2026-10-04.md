**Infrastructure** `SalesOrderRepositoryPostgres` (raw SQL, company-scoped):

**Cara dua mode ditangani di pay():** untuk tiap item, bila `sale_mode='MADE_TO_ORDER'` → ambil resep
(yield_qty) + recipe_items, requiredQty bahan = `scaledIngredientConsumption(baseQty, qty/yieldQty)`
(reuse, loss% diabaikan), lalu tambah konsumsi topping = `qty_per_item × item.qty` per topping terpilih;
target potong = batch BAHAN/TOPPING. Bila `STOCK` → satu target: product_id = produk jual, requiredQty =
item.qty; target potong = batch PRODUK JUAL. Keduanya lewat helper privat `_consumeFefo` yang identik
mekaniknya — bedanya hanya `product_id` batch.
**FEFO lintas batch:** `_consumeFefo` SELECT semua batch kandidat (ORDER BY expired_date ASC NULLS LAST,
received_date, created_at) FOR UPDATE, iterasi ambil `min(available, remaining)` sampai `remaining`
habis; tiap slice → update batch (+CONSUMED saat 0), 1 movement SALE, 1 sales_consumptions. Bila sisa
`remaining > 0` setelah semua batch → throw INVENTORY.INSUFFICIENT_STOCK (seluruh transaksi rollback).
