## Dimensi UOM menjadi data + UI Kelola Dimensi (migrasi 079)

Latar: desain 2026-11-12 mengunci dimensi ke enum WEIGHT/VOLUME/COUNT dan satuan
kanonik ke konstanta UI, sehingga tidak ada cara memasukkan meter/centimeter/
kilometer. User memilih opsi **"UI Kelola Dimensi dinamis"**: tentukan satuan
terkecil lebih dulu, baru tambah satuan lain.

Backend:
- Migrasi `079_create-table-uom-dimensions`: tabel `uom_dimensions` (code PK,
  name, canonical_unit_name, canonical_unit_symbol, sort_order, is_active,
  timestamps), seed WEIGHT/VOLUME/COUNT, drop CHECK `uoms_dimension_check`, dan FK
  `uoms_dimension_fk` (`uoms.dimension` → `uom_dimensions.code`, RESTRICT/CASCADE).
- Domain `uom-dimensions` (entity + value object), repo Postgres dengan transaksi
  `addDimension` yang sekaligus membuat UOM kanonik perusahaan (`factor_to_canonical
  = 1`, kode `UOM-###`), use case CRUD, controller `/uom-dimensions`
  (`uom.read` untuk GET, `uom.manage` untuk mutasi), wiring modul.
- `UomRepositoryPostgres`: pelanggaran FK `uoms_dimension_fk` diterjemahkan ke
  `InvariantError('UOM.DIMENSION_INVALID')`; kode ini kini terdaftar di
  `DomainErrorTranslator` (sebelumnya lolos ke respons mentah "UOM.DIMENSION_INVALID").
- Validasi format kode dimensi `/^[A-Z][A-Z0-9_]{0,19}$/` + normalisasi uppercase;
  faktor `>= 1` di entity dan DTO (`@Min(1)`).
- `InfrastructureModule`: `UomDimensionRepository` wajib diekspor; tanpa itu Nest
  gagal start (`can't resolve dependencies … UomDimensionRepository at index [3]`).

Frontend:
- Service `uom-dimension.service.ts`, composable `useUomDimensions`, komponen
  `UomDimensionTable`, `UomDimensionFormModal`, `UomDimensionDeleteModal`, halaman
  `/master/uom-dimensions` + route + menu sidebar "Dimensi UOM".
- `uom.service.ts` tidak lagi mengekspor konstanta dimensi/kanonik; `UomFormModal`,
  `UomConversionFormModal`, `UomTable`, `UomList`, dan `UomConversionList` memakai
