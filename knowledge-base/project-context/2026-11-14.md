## Palet badge dimensi diperluas ke 8 warna

User menilai palet `DIMENSION_COLORS` di `src/lib/dimensionBadge.ts` terlalu
sempit karena dimensi adalah data sehingga kode baru bisa terus bertambah.

- Palet naik dari 5 ke 8 hue: `primary/success/warning/info/error` +
  `orange/purple/pink`.
- Hash diganti dari jumlah char code menjadi FNV-1a 32-bit (`Math.imul`,
  `>>> 0`) karena jumlah char code maupun djb2 membuat WEIGHT dan VOLUME jatuh
  di indeks yang sama. FNV-1a memberi indeks berbeda; urutan palet disusun agar
  hasil default tersebar dan menghindari merah: WEIGHT→`primary`,
  VOLUME→`pink`, COUNT→`purple`, LENGTH→`orange`.
- `Badge.vue`: `BadgeColor` ditambah tiga nilai dan dipetakan ke utility baru.
- `ui.css`: 6 `@utility` baru (`tone-orange`, `tone-purple`, `tone-pink`,
  `solid-orange`, `solid-purple`, `solid-pink`), total menjadi 93 `@utility`.
  Kontras teks 12px dijaga: `tone-pink` memakai `text-pink-700` karena
  pink-500 gagal AA, `tone-purple` memakai `text-purple-600` (sama seperti
  pemakaian purple di `RolePermissionPicker`), `solid-pink` memakai
  `bg-pink-600`.
- Dokumen 52 §11.8 diperbarui sesuai perilaku baru.

Gates: `npx eslint` pada `dimensionBadge.ts` dan `Badge.vue` bersih,
`prettier --check` bersih setelah `--write`, `npm run type-check` bersih,
`npm run build-only` lulus (CSS dist memuat `.tone-orange` dan `.tone-pink`).
Perubahan belum di-commit.

## Kode UOM dapat diisi manual dan boleh dipakai ulang setelah dihapus

User ingin memberi inisial sendiri (KG, PCS, LTR) saat menambah UOM, dengan jaminan tidak ada
kode kembar saat create/edit, tetapi kode boleh dipakai lagi setelah UOM dihapus.

- Backend: `CreateUom`/`UpdateUom` menerima `code?` (uppercase, pola
  `^[A-Z][A-Z0-9_-]{0,19}$` lewat `Domains/uoms/uomCode.ts`). `CreateUomUseCase` memakai kode
  kiriman klien bila ada, selain itu tetap `generateUomCode()` (`UOM-###`). DTO create/update
  memvalidasi pola sebelum entity.
- Keunikan: migrasi 080 mengganti `uoms_code_company_unique` menjadi partial unique index
  `(code, company_id) WHERE deleted_at IS NULL` (pola payment_terms 028 / products 069).
  `UomRepositoryPostgres` memetakan pelanggaran unik 23505 di `addUom`/`updateUom` menjadi
  `UOM.CODE_ALREADY_USED` (409), dan error pola menjadi `CREATE_UOM.CODE_INVALID` /
  `UPDATE_UOM.CODE_INVALID` (400) di `DomainErrorTranslator`.
- Frontend: `UomFormModal` punya field Kode (create dan edit; hint beda per mode), uppercase,
  maxlength 20, validasi pola lokal; `UomList.onSubmitForm` mengirim `code` hanya bila terisi.
  Error duplikat tampil di `BaseAlert` dari pesan server.
- Tes: 8 suite / 65 tes UOM hijau (termasuk kode manual melewati generate dan pemetaan 23505
  pada insert/update). Gates: backend tsc/eslint/prettier bersih; frontend type-check, eslint,
  prettier, build-only lulus.
- Migrasi 080 belum dieksekusi ke database mana pun: tidak ada PostgreSQL lokal saat increment
  ini dan database user tidak disentuh.
