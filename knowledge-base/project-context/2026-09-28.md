## [Sprint 3 - Fase 2B-1] Stock Transfer (inter-outlet, dispatch/receive atomik) — Kiro (Auto model)

Lanjut Fase 2B. Dipecah lagi: 2B-1 = Stock Transfer (paling self-contained), 2B-2 = Stock Opname + Inventory Dashboard.

Implementasi mengikuti aturan domain #16-#18:
- **Lifecycle**: DRAFT→SUBMITTED→IN_TRANSIT→COMPLETED, plus DRAFT/SUBMITTED→CANCELLED. IN_TRANSIT & COMPLETED tidak bisa cancel via workflow normal.
- **SUBMITTED lock tanpa mutasi stok**. **Dispatch** (SUBMITTED→IN_TRANSIT) buat TRANSFER_OUT di source. **Receive** (IN_TRANSIT→COMPLETED) buat TRANSFER_IN di destination. In-transit stock tidak available di kedua outlet (karena source sudah dikurangi saat dispatch, destination baru ditambah saat receive).
- **Batch identity preserved** (rule #18): item men-snapshot batch_number/lot_key/lot_number/expired_date dari source batch saat create draft. Saat receive, destination batch di-resolve by (destinationOutlet + product + batchNumber + lotKey) FOR UPDATE — kalau ada di-increment, kalau tidak ada di-CREATE dengan identity sama. Global qty preserved: source decrease == destination increase.
- **Atomik & concurrency-safe**: dispatch & receive masing-masing satu transaksi SERIALIZABLE dengan SELECT FOR UPDATE + negative-stock ban di dispatch.

Yang dibangun: migrasi 1700000000018/19, domain (transferStatus + 3 entity + abstract repo), 8 use case, StockTransferRepositoryPostgres (TRF-YYYY-NNNNNN, dispatch/receive atomik), 8 endpoint controller /inventory/transfers dgn permission inventory.transfer.read/create/dispatch/receive, 3 DTO, module, Swagger, error codes, unit test semua layer.
