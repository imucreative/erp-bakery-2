## [14:30] Analisis + desain default routing `@project-manager` (amandemen ADR 55, D7) — project-manager

User meminta agar setiap prompt baru di opencode selalu dijalankan oleh `@project-manager` secara default — sesi ANALISIS + DESAIN + DOKUMEN saja, tanpa menyentuh file config/plugin/agent (territory primary agent), tanpa delegasi ke sub-agent, tanpa commit. Saya (PM) memverifikasi ulang konfigurasi saat ini (`opencode.json` tanpa `default_agent`; PM `mode: subagent` dengan `permission.task: allow`; plugin `erp-qa-gate.ts` sudah ada dengan filter ROOT + `userInitiated`), membaca ulang ADR 55 §1–§12, lalu menilai tiga opsi memakai dokumentasi resmi opencode sebagai fakta: (a) `default_agent: "project-manager"` + mode PM → `all` — satu-satunya mekanisme enforceable di level config (syarat `default_agent`: agent ada, bukan `subagent`, tidak hidden; primary tetap bisa memanggil sub-agent via `task`; `subagent_depth: 2` tetap cukup karena rantai menyusut dari 2 tingkat menjadi 1); (b) instruksi/plugin auto-forward — ditolak sebagai utama karena tidak enforceable (himbauan prompt + hook `chat.message` informasional, tanpa API ganti agent; risiko double-dispatch/loop/token); (c) alternatif (`agent` override, slash command, hook `config`, Tab manual) — semuanya ditolak sebagai utama, dengan Tab/`/agents`/`@mention` dipertahankan sebagai jalur bypass. Keputusan: opsi (a) dengan `mode: all` (bukan `primary`) agar PM tetap bisa dipanggil manual sebagai fallback; kompatibel dengan plugin QA gate (filter ROOT/userInitiated tetap benar, tanpa perubahan plugin) dan `instructions` doc 56 (injeksi berbasis direktori, tak terpengaruh mode); catatan §6.6.2 butir 1 ADR 55 menjadi stale setelah D7. Didokumentasikan sebagai amandemen §13 di ADR 55 (status tetap ACCEPTED, D7 PROPOSED) + satu baris indeks doc 41; spec eksak untuk primary agent: `opencode.json` tambah `"default_agent": "project-manager"`, 1 baris `mode: subagent` → `mode: all`, restart opencode, gate baru V14–V19.
