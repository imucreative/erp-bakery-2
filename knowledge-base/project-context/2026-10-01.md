## [16:54] Aturan PO berbasis SISA (outstanding) qty PR lintas-PO — backend-dev

Rumus yang ditegakkan (backend otoritatif):
`outstanding(prItem) = qtyPR − Σ(qty produk itu di semua PO AKTIF dari PR sama)`.
PO AKTIF = status ∈ (DRAFT, SUBMITTED, APPROVED) → DRAFT ikut mengonsumsi.
CANCELLED & REJECTED tidak dihitung (kuota kembali). Saat EDIT PO X, konsumsi PO
X sendiri dikecualikan. Match by productId.

Yang saya kerjakan:
- **Repository**: method baru `getConsumedQtyByPrItem(purchaseRequestId, companyId,
  excludePurchaseOrderId?)` di abstract `PurchaseOrderRepository` + impl Postgres.
  SQL: `SUM(poi.quantity) FROM purchase_order_items poi JOIN purchase_orders po
  WHERE po.purchase_request_id=$1 AND po.company_id=$2 AND po.deleted_at IS NULL
  AND po.status IN ('DRAFT','SUBMITTED','APPROVED') [AND po.id<>$exclude] GROUP BY
  poi.product_id` → `Map<productId, number>`. Status filter otomatis mengecualikan
  CANCELLED (yang juga soft-deleted) & REJECTED; `deleted_at IS NULL` cegah hitung
  PO terhapus; GROUP BY per produk cegah double-count.
- **Domain** `entities/CreatePurchaseOrder.ts`: hapus `validateItemsAgainstPr`
  (per-baris lama), ganti dengan `buildOutstandingMap(prItems, consumedByProduct)`
  (hasil `OutstandingPrItem[]` dengan outstanding di-clamp ≥ 0) + helper
  `validateItemsAgainstOutstanding(items, outstanding)` yang menegakkan: ITEM_NOT_IN_PR,
  DUPLICATE_ITEM, dan **QTY_EXCEEDS_OUTSTANDING** (qty > sisa). `qty > 0` tetap dijaga
  verifyItem.
- **Use case Create & Update**: setelah muat PR, panggil `getConsumedQtyByPrItem`
  (Update kirim `id` PO sbg exclude), bangun outstanding, lalu `validateItemsAgainstOutstanding`.
  Prefill-from-PR (body tanpa items): hanya item outstanding > 0, **quantity = outstanding**
  (bukan qtyPR). Bila prefill menghasilkan 0 item → error `PURCHASE_ORDER.NO_OUTSTANDING_ITEMS`.
- **Endpoint outstanding (Opsi A, rekomendasi PM)**: use case baru
  `GetPurchaseOrderOutstandingUseCase` + route `GET /api/v1/purchase-orders/outstanding`
  (diletakkan SEBELUM `GET /:id` agar tak tertangkap route param), DTO query, wiring
  InfrastructureModule. Company-scoped (PR via repo PR company-scoped → 404 bila asing).
- **DomainErrorTranslator**: tambah mapping `PURCHASE_ORDER.QTY_EXCEEDS_OUTSTANDING`
  & `PURCHASE_ORDER.NO_OUTSTANDING_ITEMS` (InvariantError → 400). `QTY_EXCEEDS_PR` lama
  dibiarkan (tak dilempar lagi) demi aman.
