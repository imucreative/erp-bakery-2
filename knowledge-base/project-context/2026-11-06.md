# Project Context — 2026-11-06

## Platform Console v2 — identity and access management

User meminta agar administrator/Super Admin dapat menambahkan user baru dan
menetapkannya ke company, serta dapat mengedit, menghapus, dan mengatur status
aktif/inaktif user.

Implementasi:

- Backend menambah endpoint platform untuk daftar role company,
  `POST /platform/users`, `PUT /platform/users/:id`, dan
  `DELETE /platform/users/:id`.
- Create memakai validasi role dan hashing password dari `CreateUserUseCase`.
- Edit mendukung nama, telepon, company, role, dan status aktif; reassign company
  menghapus assignment outlet lama agar tidak bocor lintas tenant.
- Delete adalah soft-delete dan sesi refresh user dicabut saat user dinonaktifkan
  atau dihapus.
- Seluruh create, edit, dan delete dicatat ke `audit_logs`; akun Super Admin
  tidak dapat dimutasi melalui endpoint ini.
- Frontend `UserList` sekarang memiliki form tambah/edit, assignment company dan
  role dinamis, toggle aktif/inaktif, serta soft-delete.
- Knowledge-base [55.platform-console-design.md](../55.platform-console-design.md)
  diperbarui dari v1 read-only menjadi v2 identity/access management.

Verifikasi:

- Backend type-check: lulus.
- Frontend type-check: lulus.
- Frontend production build: lulus.
- Backend full Jest suite: gagal pada test lama
  `RegisterCompanyUseCase.test.ts` yang mengharapkan perilaku permission OWNER
  sebelumnya; kegagalan tidak berasal dari perubahan Platform Console.

Langkah berikutnya:

- Jalankan migration/seed dan uji endpoint platform dengan token Super Admin.
- Uji browser create/edit/reassign/activate/deactivate/delete.
- Lanjutkan Platform Roles & Permissions dan audit-log viewer.

## Platform User Form — readability and validation refinement

Atas permintaan User, `PlatformUserFormModal.vue` dirapikan tanpa mengubah alur
API. State form sekarang memakai satu `FormState` reactive yang lebih mudah
dipelajari, validasi dipusatkan pada computed `errors` dan `isFormValid`, serta
pesan validasi ditampilkan per field melalui `BaseFormField`.

Validasi yang ditambahkan/diperjelas:

- Nama wajib, maksimal 100 karakter.
- Email wajib, format email, maksimal 100 karakter.
- Telepon opsional, maksimal 30 karakter.
- Company dan role wajib dipilih.
- Password wajib saat create, minimal 8 karakter, mengandung angka dan simbol,
  serta maksimal 100 karakter.

Field password kini memakai `PasswordInput` reusable berbasis `BaseInput` dan
`BaseButton`, sehingga nilai dapat ditampilkan/disembunyikan secara accessible
tanpa membuat primitive baru.

Verifikasi: Prettier, frontend type-check, dan frontend production build lulus.

## Signup password validation

satu angka, dan minimal satu simbol. Pesan error ditampilkan pada field password

dapat melewati validasi frontend.
