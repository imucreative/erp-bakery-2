## [16:49] Analisa `.kiro/steering` & `.kiro/hooks` + rancangan eksposnya ke opencode (ADR 55, PROPOSED) — project-manager

Sesi **ANALISA + DOKUMENTASI saja**. User meminta: (1) pelajari isi `.kiro/steering/` dan
`.kiro/hooks/`, (2) nilai apakah aturan itu bisa diekspos ke opencode dan seberapa setara,
(3) susun rancangan konkret (spesifikasi, bukan eksekusi), (4) simpan sebagai dokumen
knowledge-base, (5) jangan sentuh `backend/**`, `frontend-tailadmin/**`, `.opencode/**`,
`.kiro/**`, atau `opencode.json`. Sesi ini **tidak menulis file config/plugin apa pun** dan
**tidak mendelegasikan** ke sub-agent.

### Yang dipelajari

**`.kiro/steering/project-context-logger.md`** (3.528 byte, satu-satunya steering file,
frontmatter `inclusion: always`) — aturan normatif yang mengikat **semua AI**: setiap kali
menganalisa kode, mengubah kode, menjalankan verifikasi penting, atau mengambil keputusan
desain, AI WAJIB append entri naratif ke `knowledge-base/project-context/YYYY-MM-DD.md`.
Pengecualian eksplisit untuk basa-basi. Format entri `## [HH:MM] Judul — <model/agent>` +
narasi + 4 baris metadata. Append-only, satu file per hari, ada template header harian,
dan ada alur 3 langkah (baca konteks hari ini + hari sebelumnya, kerjakan, append). Larangan
mengubah entri lama.

**`.kiro/hooks/qa-after-dev.json.disabled`** (1.266 byte) — hook trigger `Stop`, action
`type: "agent"` yang menyuntik prompt: "JIKA sesi ini ada perubahan kode `backend/**` atau
`frontend/**`, delegasikan verifikasi ke `qa-engineer`, tunggu Laporan QA sebelum menyatakan
selesai; JIKA tidak menyentuh kode, ABAIKAN."Dua cabang: ada perubahan → wajib QA; tidak ada
→ diam. Status aktif **tidak pasti** karena suffix `.disabled`.

### Verifikasi faktual (bukan asumsi)

Tidak mempercayai premis, semuanya dicek ulang:

1. **Ukuran byte `.kiro/agents/*` vs `.opencode/agents/*` TIDAK identik** — selisihnya 49 / 25 /
   186 / 247 byte (5981vs6030, 6327vs6352, 8276vs8090, 7145vs6898). Premis "identik" SALAH,
   tapi kesimpulannya (duplikasi) benar.
2. **Lokasi direktori plugin opencode adalah `.opencode/plugins/` (JAMAK)**, bukan
   `.opencode/plugin/`. Premis awal salah. File di sana dimuat otomatis, tidak perlu key `plugin`.
3. **Daftar hook opencode diverifikasi dari type definition lokal** `@opencode-ai/plugin@1.18.34`
   (`dist/index.d.ts`), bukan dari ingatan. **Tidak ada hook bernama `Stop`.**
4. **Tidak ada field `resources:` di opencode.** opencode agent hanya punya
   `description`/`mode`/`model`/`temperature`/`top_p`/`prompt`/`steps`/`disable`/`tools`
   (deprecated)/`permission`/`hidden`/`color`. `resources` Kiro **tidak punya padanan**.
5. **`instructions` di `opencode.json` terbukti berlaku ke sub-agent** — dibuktikan dari source
   `packages/opencode/src/session/prompt.ts` (~baris 1257-1269): `instruction.system()` dipanggil
   di loop prompt yang sama untuk setiap sesi, dan ia bergantung pada `InstanceState.context`
   (directory/worktree), bukan `sessionID`.
6. **`experimental.hook.session_completed` ada di type `Config`** tapi bentuknya
   `{ command: string[] }` — menjalankan command eksternal, **tidak bisa** menyuntik prompt.
   Dicatat agar tidak dicoba ulang.
7. **`client.session.diff()` tersedia** (`Array<FileDiff>` dengan `file`/`additions`/`deletions`)
   plus `client.session.children()` dan `Session.parentID` — ini memberi sinyal "sesi ini menyentuh
   kode" yang **jauh lebih andal** daripada menebak dari isi percakapan seperti hook Kiro.
8. **`client.session.promptAsync()`** ada dan menerima `body.parts` — padanan non-deklaratif
   dari `action.type = "agent"`. Verified `SessionPromptAsyncData`.

### Temuan yang tidak diminta tapi penting

**Konversi `.kiro/agents/` -> `.opencode/agents/` diam-diam menghilangkan blok `resources:`.**
Di Kiro, `resources:` = file yang **otomatis dimuat ke konteks**. Di `.opencode/agents/*` blok itu
dibuang dan diganti daftar path prosa di body prompt ("Dokumen Rujukan"). Akibatnya auto-inject
7-13 dokumen knowledge-base per sub-agent **berhenti** — termasuk
`file://.kiro/steering/project-context-logger.md`, yang karena itu **tidak pernah ter-inject ke
sesi mana pun**. Hilangnya mekanisme ini **tidak pernah dicatat di dokumen mana pun**. Perlu
keputusan sadar: apakah ini memang yang diinginkan (hemat konteks) atau regresi yang tidak
disengaja.

Juga: `.opencode/agents/project-manager.md` kehilangan `toolsSettings.subagent.availableAgents`
+ `trustedAgents` (padanan terdekat: `permission.task` glob).

### Kesimpulan kesetaraan

| Artefak | Mekanisme opencode | Kesetaraan | Catatan |
|---|---|---|---|
| steering `inclusion: always` | `instructions:` di `opencode.json` | **~90%** | terbukti kena sub-agent; nol kode; idempoten via `Set`; bertahan melewati compaction |
| hook `Stop` + `action: agent` | plugin `event` (`session.idle`) + `client.session.promptAsync()` | **~90%** | deteksi perubahan kode jadi **lebih akurat** (pakai `session.diff`) |

**Yang tidak bisa ditransliterasi 1:1:**
- Tidak ada hook `Stop` bernama -> dipetakan ke `session.idle` (terbukti ada di SDK + daftar
  event resmi).
- `action.type = "agent"` tidak punya padanan deklaratif -> harus kode imperatif di dalam plugin,
  jadi idempotensi + error handling jadi **kode yang harus diuji**.
- `resources:` (auto-inject file per agent) **tidak punya padanan sama sekali**.
- `inclusion: always` sebagai field tidak ada; file yang dirujuk harus bebas frontmatter Kiro
  (kalau tidak, YAML-nya ikut terkirim ke model sebagai teks literal).
- Tidak ada fail-closed untuk aturan logger; latch plugin tidak persisten antar restart.

### Keputusan rancangan (PROPOSED, belum dieksekusi)

- **Steering -> `instructions:` di `opencode.json`**, bukan plugin `system.transform`, bukan
  `AGENTS.md` root. Alasannya: coverage ke sub-agent sudah terbukti, idempotensi gratis, nol
  kode, dan bertahan melewati compaction. Plugin `system.transform` justru lebih mahal karena
  hook-nya tidak menyertakan `agent`, jadi menyaring per-agent butuh `session.get()` di SETIAP
  panggilan LLM.
- **Hook -> plugin `.opencode/plugins/erp-qa-gate.ts`** dengan 3 hook: `event` (trigger utama),
  `chat.message` (re-arm latch + tandai sesi ber-input user), `tool.execute.after` (sinyal
  cadangan). Anti-loop 7 lapis: latch per-session + TTL 12 jam + in-flight guard + latch dipasang
  SEBELUM injeksi + syarat diff + filter `parentID` + filter `userInitiated`.
- **Duplikasi agent -> `.opencode/agents/` jadi single source of truth**; `.kiro/` diarsipkan
  setelah satu siklus penuh. Opsi "`.kiro/` jadi SSOT" **tidak layak secara teknis** karena
  opencode tidak akan membaca format Kiro sama sekali.
- **Rujukan silang 4 baris** di `.opencode/agents/*` (baris 64/73/75/66) menunjuk
  `.kiro/steering/project-context-logger.md` — wajib diperbarui sebelum `.kiro/steering/` dihapus.
