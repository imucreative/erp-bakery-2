## [14:05] Diagnosis bug POST payment-term (unique constraint) — project-manager (orkestrator)

User menjalankan migrasi payment_terms, lalu POST /payment-terms error 500:
`duplicate key value violates unique constraint "payment_terms_code_company_unique"`.

Diagnosis PM (root cause): constraint di migrasi `1700000000027` adalah
`UNIQUE (code, company_id)` — constraint kolom BIASA yang TIDAK mengecualikan
soft-deleted row. Padahal repository & use case sudah soft-delete-aware
(`isCodeTaken` memakai `deleted_at IS NULL`). Mismatch ini bikin skenario: buat
NET30 → soft-delete NET30 → buat NET30 lagi → `isCodeTaken` balas false (abaikan
yang deleted) → lolos ke INSERT → DB menolak karena row lama (deleted) masih
menempati (code, company). Hasilnya 500, bukan 409 rapi.

Kenapa hanya muncul di Payment Term: modul master lain (Supplier/UOM/Outlet) juga
memakai `UNIQUE (code, company_id)` tanpa filter soft-delete, TAPI code mereka
AUTO-GENERATE (selalu unik baru) sehingga collision jarang terpicu. Payment Term
`code` = USER INPUT, jadi user gampang memasukkan code yang sama dengan yang sudah
dihapus → collision langsung.

Perbaikan yang diputuskan: ubah unique Payment Term menjadi PARTIAL UNIQUE INDEX
`UNIQUE (code, company_id) WHERE deleted_at IS NULL`, menyelaraskan DB dengan
logika soft-delete di repo/use case. Perlu migrasi baru (jangan edit migrasi lama
yang sudah dijalankan user). Didelegasikan ke backend-dev.

- File yang dibuat/diubah: (belum — diserahkan ke backend-dev)
- Hasil verifikasi: belum
- Keputusan penting: pakai partial unique index (soft-delete aware); migrasi BARU, bukan edit migrasi lama.
- Langkah berikutnya: delegasi fix ke backend-dev, verifikasi, commit.

## [14:16] Fix bug unique constraint Payment Term (partial unique index) — backend-dev

User (via project-manager) melaporkan `POST /api/v1/payment-terms` bisa error 500
`duplicate key value violates unique constraint "payment_terms_code_company_unique"`.
Root cause: migrasi `1700000000027_create-table-payment-terms.js` mendefinisikan
`payment_terms_code_company_unique` sebagai `UNIQUE (code, company_id)` biasa yang
ikut menghitung row soft-deleted. Padahal `PaymentTermRepositoryPostgres.isCodeTaken`
dan `CreatePaymentTermUseCase` hanya melihat row dengan `deleted_at IS NULL`.
Akibatnya skenario buat `NET30` → soft-delete → buat `NET30` lagi lolos cek aplikatif
(`isCodeTaken` = false) tapi ditolak DB karena row lama (deleted) masih menempati
`(code, company_id)` → 500.

Perbaikan: sesuai instruksi, TIDAK mengedit migrasi lama. Membuat migrasi BARU
`1700000000028_fix-payment-terms-unique-partial.js` yang: (1) `pgm.dropConstraint`
constraint lama, (2) `pgm.createIndex(['code','company_id'], { unique, name:
'payment_terms_code_company_unique', where: 'deleted_at IS NULL' })` → PARTIAL UNIQUE
INDEX hanya untuk row aktif, (3) `exports.down` reversibel (drop index + restore
constraint UNIQUE biasa). Dengan ini code soft-deleted boleh dipakai lagi, duplikat
AKTIF tetap ditolak. Cek aplikatif `isCodeTaken` + DomainErrorTranslator
(`PAYMENT_TERM.CODE_ALREADY_USED` → 409) tetap jadi jalur utama; index ini pelengkap
di level DB.

Menambah regression guard test di `PaymentTermRepositoryPostgres.test.ts` yang
mengunci bahwa query `isCodeTaken` mengandung `deleted_at IS NULL` (mengabaikan
soft-deleted). Modul master lain (Supplier/UOM/Outlet) sengaja TIDAK disentuh karena
code mereka auto-generate.

DROP CONSTRAINT lalu CREATE UNIQUE INDEX ... WHERE deleted_at IS NULL, "Migrations
complete!". Verifikasi manual via script pg sementara (sudah dihapus): step create→
soft-delete→create code sama BERHASIL (bug hilang), create duplikat AKTIF ditolak
error 23505 pada `payment_terms_code_company_unique` (benar).

- File yang dibuat/diubah:
  - `backend/migrations/1700000000028_fix-payment-terms-unique-partial.js` (baru)
  - `backend/src/Infrastructures/repository/_test/PaymentTermRepositoryPostgres.test.ts` (tambah 1 regression test)
- Hasil verifikasi: tsc bersih; jest 851/851 pass (120 suites); migrasi 1700000000028 applied OK; skenario manual create→delete→create sukses & duplikat aktif ditolak.

normalisasi `String(...)` di submit menerima string maupun number.
