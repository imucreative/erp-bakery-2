Yang dikerjakan:

1. **Jeda hook QA otomatis.** File `.kiro/hooks/qa-after-dev.json` di-rename menjadi
   `.kiro/hooks/qa-after-dev.json.disabled` supaya loader hook Kiro tidak lagi
   memicunya tiap akhir sesi. Reversibel: cukup rename balik untuk mengaktifkan.
   Verifikasi jadi on-demand (manual) sementara ini.

2. **Pertanyaan #1 (fitur Outlet).** Dijawab, tanpa perubahan kode: backend Outlet
   SUDAH ada (CRUD penuh, permission `outlet.read`/`outlet.manage`). Di frontend

   tampak seperti input teks. Solusi: bungkus tiap select dengan container
   `relative`, tambahkan `pe-10` pada select, dan overlay `ChevronDownIcon`
   (`absolute inset-y-0 end-3 my-auto`, `pointer-events-none`, RTL-aware pakai
   `end-*`). Diterapkan ke select: Category (grup produk), Product (grup,
   kategori, uom, supplier, tipe produk), dan User (role).

4. **Fix #3 (checkbox → toggle switch).** Dibuat komponen bersama
   `src/components/ui/ToggleSwitch.vue` (v-model boolean, dark mode, label
   opsional, RTL-aware, role="switch"). Semua `<input type="checkbox">` di form
   ERP diganti ToggleSwitch: toggle "Aktif" (UOM, Supplier, Product-Group,
   Category, Product, User), "Lacak batch" (Product), dan daftar akses outlet di
   User (dari checkbox list menjadi baris label + ToggleSwitch). Checkbox yang
   tersisa hanya di file demo template TailAdmin (`forms/FormElements/*`,
   `profile/Security.vue`) — di luar scope form ERP, tidak disentuh.

Standar UI ini juga sudah didokumentasikan di `knowledge-base/48.tailadmin-frontend-backlog.md`
(dibuat sesi sebelumnya): tombol aksi icon-only, select wajib punya chevron,
gunakan toggle switch bukan checkbox, modal transparan, catatan port backend 5000,
dan status QA otomatis dijeda.

## [13:13] Modul Payment Term backend (master data baru, greenfield) — backend-dev

Project-manager mendelegasikan pembangunan modul **Payment Term** backend
secara penuh (master data baru; sebelumnya hanya ada seed permission
`payment-term.read`/`payment-term.manage` di `permissions.seed.ts`). Saya
pelajari dulu modul Supplier & UOM sebagai acuan pola (Clean Architecture:
Domains/Applications/Infrastructures/Interfaces, raw SQL via `pg`,
node-pg-migrate), lalu meniru struktur file, layering, dan gaya test-nya.

Yang dikerjakan:
- Migrasi `payment_terms`: kolom `code` (VARCHAR 20), `name`, `due_days`
  (INTEGER, CHECK >= 0), `is_active`, audit (`created_at`/`updated_at`/
  `deleted_at`) — persis pola tabel Supplier (tanpa kolom created_by dkk karena
  Supplier pun tidak punya). Unique `(code, company_id)` + index company_id,
  code, is_active, deleted_at.
- Domain `payment-terms/`: entities `PaymentTerm`, `CreatePaymentTerm`,
  `UpdatePaymentTerm`, abstract `PaymentTermRepository` (+ folder `_test`).
- Application `use_case/payment-terms/`: Create/Update/Delete use case + unit test.
- Infrastructure: `PaymentTermRepositoryPostgres` + registrasi provider/export di
  `InfrastructureModule` (@Global). Unit test repository pakai mock pool.
- Interface HTTP `payment-terms/`: controller + module + 3 DTO (create/update/
  query). Endpoint: list (paginated, search, isActive), lookup (active-only),
  detail, create, update, delete (soft). Route `lookup` dideklarasikan sebelum
  `:id` agar tidak bentrok. Semua tenant-scoped via `_companyId(user)`, response
  pakai `successResponse`/`listResponse`, Swagger lengkap. Tag 'Payment Terms'
  didaftarkan di `main.ts` dan `PaymentTermModule` di `app.module.ts`.
- Error mapping di `DomainErrorTranslator`: CREATE/UPDATE validation,
  `PAYMENT_TERM.NOT_FOUND` (404), `PAYMENT_TERM.CODE_ALREADY_USED` (409),
  `PAYMENT_TERM.IN_USE` (409).
- Seed role mapping (idempoten, tidak menghapus assignment lain): ADMIN_GUDANG
  dapat `payment-term.read` + `payment-term.manage`; SUPERVISOR_OUTLET, PRODUKSI,
  KASIR dapat `payment-term.read`; OWNER otomatis via sentinel 'ALL'.

Keputusan penting:
- Berbeda dari Supplier/UOM yang auto-generate code, **`code` Payment Term diinput
  user**, dinormalisasi trim+uppercase, dan dicek unik per company di use case
  (`isCodeTaken` → `PAYMENT_TERM.CODE_ALREADY_USED`). `code` **immutable** saat
  update (tidak diterima di UpdateDto/UpdatePaymentTerm).
- `dueDays` divalidasi integer >= 0 di domain (Create & Update) dan DB (CHECK).
- Proteksi dependency (doc 44) belum diimplementasi penuh karena belum ada modul
  yang mereferensi Payment Term; `countActiveDependents` sengaja return 0 sebagai
  hook agar mudah diaktifkan nanti tanpa refactor (guard delete/deactivate sudah
  terpasang di use case).
- KASIR diberi `payment-term.read` mengikuti spesifikasi eksplisit doc 16 §10
  Payment Term ("SUPERVISOR_OUTLET, PRODUKSI, KASIR: payment-term.read") dan
  instruksi PM, meski daftar ringkas doc 16 §8 untuk KASIR tidak mencantumkannya.
- Tidak menulis audit log karena modul Supplier (acuan) tidak menulis audit log.

Hasil verifikasi:

- Jest full suite (runInBand): **120/120 suites, 850/850 tests pass, 0 gagal**
