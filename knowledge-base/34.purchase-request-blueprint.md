# 34. Purchase Request Blueprint

This document defines the technical specification, UI layout, validation rules, and API specifications for the Purchase Request (PR) module. No implementation may deviate from these blueprints.

---

## 1. Purchase Request Structure

A Purchase Request document consists of a Header (metadata) and a Details grid (line items):

### A. Header Fields
- `id` (UUID, Primary Key)
- `prNumber` (String, Unique, e.g. `PR-WH-RETAIL-01-2026-000001`)
- `requestorId` (UUID, references User)
- `destinationLocationId` (UUID, references Outlet)
- `expectedDate` (Date, expected delivery arrival date)
- `totalEstimatedAmount` (Decimal, net amount of all line items)
- `status` (Enum: `DRAFT`, `SUBMITTED`, `APPROVED`, `REJECTED`, `CANCELLED`)
- `createdAt`, `updatedAt`, `createdBy`, `updatedBy`

### B. Details (Line Items)
- `id` (UUID, Primary Key)
- `purchaseRequestId` (UUID, references Purchase Request)
- `productId` (UUID, references Product)
- `quantity` (Decimal, quantity requested)
- `uomId` (UUID, references UOM)
- `estimatedPrice` (Decimal, unit price estimate)
- `subtotal` (Decimal, quantity * estimatedPrice)

## 2. Validation & Business Rules

### Zod Validation Schema
```typescript
const purchaseRequestSchema = z.object({
  destinationLocationId: z.string().uuid("Invalid location ID"),
  expectedDate: z.date().min(tomorrow, "Expected date must be tomorrow or later"),
  items: z.array(z.object({
    productId: z.string().uuid("Invalid product ID"),
    quantity: z.number().positive("Quantity must be positive"),
    uomId: z.string().uuid("Invalid UOM ID"),
    estimatedPrice: z.number().nonnegative("Estimated price cannot be negative")
  })).min(1, "At least one item is required")
});
```

### Constraints:
- Expected delivery date must be tomorrow or later; today and previous dates are not selectable.
- The `subtotal` and `totalEstimatedAmount` must be calculated on the server side to prevent client tampering.

### Form Drawer Detail:
- **Left Panel**: Header inputs (Outlet select, Expected Date date-picker).
- **Center Panel**: Line Item Grid (Product selection search dropdown, Quantity inputs, UOM read-only, Estimated Price automatic fetch, Subtotal display).
- **Right Panel**: Meta controls:
  - **Attachments section**: Quote or inventory level print uploads.
  - **Comments thread**: Internal notes for the supervisor.
  - **Approval Timeline**: Visually tracks transitioning states.

## 4. REST APIs
- `GET /api/v1/purchase-requests` -> Lists PRs with pagination and filters.
- `GET /api/v1/purchase-requests/:id` -> Retrieves a single PR with details, attachments, comments, and status logs.
- `POST /api/v1/purchase-requests` -> Creates a new PR in `DRAFT` state.
- `PUT /api/v1/purchase-requests/:id` -> Updates an existing PR (only allowed in `DRAFT` or `REJECTED` states).
- `POST /api/v1/purchase-requests/:id/submit` -> Submits the PR for review (status -> `SUBMITTED`).
- `POST /api/v1/purchase-requests/:id/approve` -> Approves the PR (status -> `APPROVED`, triggers PO event).
- `POST /api/v1/purchase-requests/:id/reject` -> Rejects the PR (status -> `REJECTED`).
- `POST /api/v1/purchase-requests/:id/cancel` -> Voids/cancels the PR (status -> `CANCELLED`).

---

## 5. Permissions
- `procurement.pr.read` -> Allowed for users in the same outlet; `OWNER` bypasses outlet scope.
- `procurement.pr.create` -> Allowed for `OWNER`, `SUPERVISOR_OUTLET`, `ADMIN_GUDANG`.
- `procurement.pr.update` -> Allowed for Creator in `DRAFT` or `REJECTED`; `OWNER` bypasses ownership and outlet scope.
- `procurement.pr.approve` -> Allowed for `OWNER` (any amount), `SUPERVISOR_OUTLET` (amount < Rp 500.000 and same outlet).
