## 2. Standar UI (frontend-tailadmin)

Standar ini WAJIB diikuti semua modul TailAdmin agar konsisten. Melengkapi AGENTS.md.

### 2.0 Core input foundation — WAJIB

Semua form baru dan form yang dimigrasikan wajib menggunakan komponen input reusable
di `frontend-tailadmin/src/components/ui/`, bukan mengulang class Tailwind panjang
pada setiap feature component atau view.

Komponen kanonik:

- `BaseButton.vue` — tombol standar untuk action, submit, loading, disabled, variant,
  ukuran, dan full-width layout.
- `BaseFormField.vue` — label, required marker, hint, dan error message.
- `BaseInput.vue` — input text dan tipe input HTML standar.
- `BaseTextarea.vue` — textarea standar.
- `BaseSelect.vue` — native select dengan chevron dan state standar.
- `BaseToggle.vue` — boolean toggle; checkbox mentah tidak digunakan pada form.
- `BaseCheckbox.vue` — checkbox standar untuk pilihan biner di dalam daftar (mis. katalog
  permission pada Roles). State aktif/nonaktif sebuah entitas tetap memakai toggle switch
  (§2.3); `BaseCheckbox` dipakai saat konteksnya "centang banyak item".
- `BaseAlert.vue` — banner notifikasi inline. `variant` = `error` (default) | `success` |
  `warning` | `info`; `size` = `sm` (di dalam modal) | `md` (di halaman, default).
  Menyembunyikan diri saat `message` kosong dan slot default tidak diisi, jadi pemakai tidak
  perlu menulis `v-if` sendiri. Punya slot `icon`, props `dismissible` + event `dismiss`,
  dan mengirim `role="alert"` untuk error/warning, `role="status"` untuk lainnya.
- `BaseModal.vue` — kerangka modal standar: wrapper `fixed inset-0 z-99999`, backdrop
  transparan `bg-gray-900/20 backdrop-blur-[2px]` (dark `bg-black/30`), panel `rounded-3xl`
  - `shadow-theme-lg` dengan `role="dialog"` + `aria-modal="true"`. `size` = `md` (default) |
    `lg` | `xl` | `2xl`; `scrollable` menambahkan `max-h-[90vh] overflow-y-auto`; tutup lewat
    klik backdrop atau tombol Esc (`dismissible`, default `true`). Kontrol buka/tutup tetap
    milik parent (`:open` + `@close`), begitu pula mutation dan validasi.
- `BaseTablePagination.vue` — pagination presentational untuk tabel dengan state
  current page, total page, previous/next, dan total item.
- `BaseTable.vue` — shell presentational untuk wrapper responsive, table styling,
  loading, error, dan empty state melalui named slots.
- `BaseTableRow.vue`, `BaseTableHead.vue`, dan `BaseTableCell.vue` — primitive
  semantic untuk `<tr>`, `<th>`, dan `<td>` dengan alignment serta emphasis standar.
- `SearchInput.vue` — search UX reusable; perilaku fetch tetap berada di composable.
- `EntityCombobox.vue` — pencarian/pemilihan entity; data loading tetap berada di caller.
- Action button menggunakan `BaseButton`; varian `success`, `info`, `warning`, dan
  `danger` digunakan sesuai konteks semantik, sedangkan `iconOnly` digunakan untuk
  aksi tabel yang hanya menampilkan ikon.

Aturan penggunaan:

1. Komponen foundation hanya menangani rendering, interaction UI, styling, dan
   accessibility. Komponen tidak boleh memuat business rule atau request API.
2. Business logic, validasi domain, mutation, dan error mapping tetap berada di
   feature component, composable, service, atau backend.
3. `BaseInput`, `BaseTextarea`, `BaseSelect`, dan `BaseToggle` harus memiliki state
   visual yang konsisten untuk normal, focus, disabled, readonly, error, dan dark mode.
4. `BaseButton` wajib digunakan untuk tombol action dan submit pada fitur yang sudah
   dimigrasikan. Jangan mengulang class tombol panjang di view atau feature component.
   Loading harus men-disable tombol dan menampilkan loading text yang relevan.
5. Field wajib memiliki label yang terhubung dengan input melalui `for`/`id`; error
   harus dapat dihubungkan melalui `aria-describedby` bila error tersedia.
6. Select wajib menggunakan indikator chevron. Jangan menambahkan implementasi select
   lokal di feature module.
7. Sebelum membuat komponen input atau button baru, periksa komponen foundation. Komponen baru
   hanya boleh dibuat jika behavior-nya benar-benar berbeda dan reusable lintas modul.
8. Migrasi dilakukan bertahap per modul. Refactor tidak boleh mengubah API endpoint,
   permission, business rule, atau lifecycle form.
9. Komponen foundation harus diekspor melalui barrel `src/components/ui/index.ts`
   agar import antar-feature konsisten.
10. Ikon fitur baru dan fitur yang dimigrasikan wajib menggunakan `lucide-vue-next`;
    inline SVG tidak boleh digunakan sebagai icon di template. File logo/asset branding
    SVG bukan icon UI dan tetap boleh digunakan sebagai asset.
11. `BaseTablePagination` hanya menangani rendering dan event navigasi. Fetch,
    perubahan page, debounce, dan business logic tetap berada di view/composable.
12. Banner notifikasi WAJIB `BaseAlert`. Jangan menulis ulang `class="alert-error px-3 py-2"`
    atau `role="alert"` manual di feature component; gunakan `size="sm"` di dalam modal dan
    `size="md"` (default) di halaman.
13. Modal WAJIB `BaseModal`. Dilarang mengulang wrapper `fixed inset-0` + backdrop manual di
    view atau feature component. `BaseModal` hanya kerangka: tombol aksi, form state,
    mutation dan error mapping tetap di parent.
14. `BaseTable` sudah merender `BaseAlert` untuk state error, jadi view tidak boleh menambah
    banner error kedua untuk request yang sama.

### 2.1 Tombol aksi baris tabel — ICON-ONLY kompak

- Aksi di baris tabel (edit, hapus, lihat) memakai tombol **icon-only** (ikon
  `lucide-vue-next`), ukuran kotak `h-9 w-9`, dengan `aria-label` + `title` (tooltip).
- Tombol dengan deskripsi (mis. "+ Tambah", "Simpan", "Batal") tetap pakai teks.
- Edit = ring outline abu (Pencil); Hapus = ring merah/error (Trash2); Lihat = ring abu (Eye).

### 2.2 Select / dropdown — WAJIB ada indikator panah (chevron)

- Select memakai `<select>` native + `appearance-none` (menghapus panah bawaan browser),
  JADI WAJIB menambahkan ikon chevron (ChevronDown dari lucide) di sisi kanan agar
  terlihat berbeda dari input text biasa. Bungkus select dalam container relatif +
  posisikan chevron absolut kanan (`pointer-events-none`).
- Standar ini dibuat karena sebelumnya select tampak identik dengan input text (tanpa panah).

### 2.3 Toggle boolean — pakai TOGGLE SWITCH, bukan checkbox

- Semua input boolean di form (mis. "Aktif", "Lacak batch", dan pemilihan multi-item
  seperti akses outlet) memakai komponen **toggle switch**, BUKAN `<input type="checkbox">`.
- Komponen bersama: `src/components/ui/ToggleSwitch.vue` (v-model boolean, dukungan dark
  mode + disabled + label opsional).
- Untuk daftar pilihan (mis. outlet di form Users), tiap baris pakai toggle switch.
- **Pengecualian (2026-10-23):** katalog permission pada Roles
  (`components/system/role/RolePermissionPicker.vue`) memakai `BaseCheckbox` karena bentuk
  interaksinya "centang banyak sekaligus", bukan menyalakan satu state entitas.

### 2.4 Modal — backdrop transparan, lewat `BaseModal`

- Standar visual: backdrop ringan/transparan `bg-gray-900/20 backdrop-blur-[2px]`
  (dark `bg-black/30`), bukan blur berat; panel `rounded-3xl` + `shadow-theme-lg`.
- Standar ini sudah dibungkus `BaseModal` (§2.0), jadi feature component tidak menulis
  backdrop/panel sendiri. Ukuran panel dipilih lewat `size` (`md`/`lg`/`xl`/`2xl`) dan
  konten panjang memakai `scrollable`.

### 2.5 Pola modul master/CRUD

- Struktur: `services/<x>.service.ts` + `composables/use<X>.ts` + komponen
  `components/<area>/<x>/{XTable, XFormModal, XDeleteModal}.vue` + view tipis
  `views/<Area>/<X>List.vue` + route (meta.permission) + entri sidebar.
- Relasi: opsi di-load via composable (ensureOptions), id→nama map untuk kolom tabel,
  dropdown relasi wajib saat create, read-only saat edit bila backend tak izinkan ganti.

### 2.6 Ikon pada tombol — WAJIB, teks opsional

- **Setiap tombol WAJIB memiliki ikon** (`lucide-vue-next`) yang relevan dengan fungsinya
  (mis. Simpan=Save/Check, Batal=X, Tambah=Plus, Edit=Pencil, Hapus=Trash2, Kembali=ChevronLeft,
  Ajukan=Send, Setujui=Check, Tolak=X, Batalkan=Ban, Unduh=Download, Unggah=UploadCloud).
- **Teks tidak wajib** untuk setiap tombol berikon: tombol aksi baris tabel & tombol back
  bersifat **icon-only** (lihat §2.1 & §2.7); tombol utama/berdeskripsi (Simpan, Batal,
  Tambah X, Ajukan) tetap pakai ikon + teks.
- Tombol icon-only WAJIB punya `aria-label` + `title`.

### 2.7 Halaman DOKUMEN (Detail & Form) — layout & pemecahan komponen

Berlaku untuk modul dokumen transaksional (Purchase Request, Purchase Order, Goods Receipt,
Purchase Return, dan sejenisnya). Pola ini mandatory dan diturunkan dari implementasi
Purchase Request (2026-09-30).

- **Header halaman**: baris `flex items-center justify-between`.
  - **Kiri (start)**: tombol **Back ICON-ONLY** (`ChevronLeft`, mis. `h-10 w-10`,
    `rtl:rotate-180`, `aria-label`/`title` "Kembali ke Daftar") BERSEBELAHAN dengan JUDUL
    halaman (mis. nomor dokumen untuk detail; "Buat/Edit X" untuk form). JANGAN taruh
    tombol back di bawah bersama tombol aksi.
  - **Kanan (end)**: **kumpulan tombol aksi** (lifecycle: Edit/Ajukan/Setujui/Tolak/Batalkan)
    dikelompokkan dalam satu action bar, rata kanan.
- **Pemecahan komponen (WAJIB)**: setiap bagian UI dipisah menjadi komponen stateless sendiri
  agar file View tetap tipis (hanya state + handler, render didelegasikan). Pola komponen
  (contoh Purchase Request):
  - Detail: `<X>Summary.vue` (kartu header meta), `<X>ItemsTable.vue` (tabel item read-only),
    `<X>ActionBar.vue` (tombol lifecycle), `<X>Timeline.vue`, `<X>Comments.vue`,
    `<X>Attachments.vue`.
  - Form: `<X>HeaderFields.vue` (field header), `<X>ItemsEditor.vue` (grid item editable).
  - Semua di `components/<area>/<x>/` + diekspor via `index.ts` (barrel).
  - View (`<X>Detail.vue`, `<X>Form.vue`) = pemilik state & handler; sub-komponen menerima
    props & meng-emit event (tanpa state sendiri).
- Konsisten dark mode + RTL logical props (ps/pe/ms/me/start/end) + token warna Tailwind.

**Snippet class inti (`ui.css`)** dibuat dengan `@utility` Tailwind v4 supaya pemanggil
cukup menulis `<h4 class="modal-title">`, bukan rantai class panjang. `@utility` yang tidak
dipakai ikut ter-tree-shake, jadi menambah satu class tidak menggembsikan bundle.
Semua offset yang dikutip di bawah ini diukur dari build saat ini,
`dist/assets/index-CEnZavT_.css` (134.697 byte); ganti angkanya kalau build berganti.
Angka 134.695 yang tertulis sebelumnya meleset 2 byte — increment Stock On Hand tidak menyentuh
`ui.css` sama sekali, dan build ulang menghasilkan hash yang sama persis, jadi ukuran 134.697 inilah
yang benar untuk konten tersebut.

**Ambang pembuatan snippet: ±60 call site** (lihat catatan `form-readonly` di bawah).
Pengecualian yang disepakati 2026-10-24: rantai dengan call site sedikit tetap boleh dijadikan
snippet kalau **kohesif dan selalu muncul berpasangan**, sehingga modul berikutnya pasti menyalin
rantai yang sama. Contoh: `timeline-rail` + `timeline-dot` (masing-masing hanya 4 situs identik di
4 komponen timeline) — dibuat sepasang sekaligus, bukan satu per satu. `icon-tile` dan `confirm-bar`
mengikuti jalur yang sama (4 situs identik di 4 komponen lampiran).
Pengecualian kedua yang disepakati pada hari yang sama: rantai **tata letak kerangka** yang
bertambah satu situs tiap modul baru, walaupun belum mencapai ambang. Contoh `toolbar-row`
(27 situs di 27 file — header semua halaman List + 4 komponen Comments; ditambah 1 situs varian di
`ShiftBar` jadi 28) dan `field-grid` (30 situs di 27 file — tiap `*HeaderFields`/`*Summary` dan
modal form master data, ditambah kerangka kotak totals `PurchaseOrderSummary`). Kalau rantai semacam
ini dibiarkan, setiap modul menambah salinan identik
selamanya dan tidak pernah "menyeberang" ke ambang ±60. Konsekuensinya dicatat jujur: CSS hasil
build sedikit membesar (132.364 → 133.073 → 133.256 → 133.998 → 134.697 byte, total +2.3 kB untuk
empat sapuan) karena rule snippet ditambahkan sementara utility core lama tetap dipakai pemanggil
lain — yang dikorbankan ukuran, yang didapat adalah 154 rantai panjang hilang dari source (28
`toolbar-row`/`confirm-bar` + 30 `field-grid` + 19 `stack-row` + 11 `panel-loading` — dua yang

**Aturan cascade (sudah diverifikasi):** Tailwind memancarkan `@utility` custom SEBELUM
utility core, sehingga class pemanggil selalu menang atas snippet tanpa perlu `!important`
dan tanpa peduli urutan penulisan di `class="..."`. Artinya `class="modal-title mt-4"`
berhasil, dan memanggil ulang `text-*` di call-site akan menimpa snippet.

**Tapi urutan itu per kategori properti, dan padding punya jebakan sendiri (2026-10-24).**
Utility shorthand `p-*` dipancarkan **sebelum** longhanded `px-*`/`py-*` (di build
saat ini `index-CEnZavT_.css`:
`.p-4` 39787 < `.px-4` 40196 < `.py-3` 40645 < `.py-4` 40740; dulu di `index-DHD-fYL5.css`:
39274 / 39683 / 40132 / 40227 — urutannya stabil, angkanya yang bergeser). Akibatnya
`class="rounded-2xl p-4"`
di atas `BaseAlert size="md"` (yang membawa `px-4 py-3`) TIDAK menghasilkan padding 16px rata —
`px-4`/`py-3` menang, kartu jadi 16×12. Bentuk yang benar: timpa properti yang memang perlu berubah
saja, `class="rounded-2xl py-4"` (`.py-4` belakangan mengalahkan `.py-3`, `px-4` sudah 16). Empat
situs `*Detail.vue` (PO, PR, GR, PR-Return) memakai bentuk `p-4` yang salah itu — tiga dikoreksi di
increment GR, `PurchaseReturnDetail` menyusul di increment Purchase Return. Aturan
umumnya: kalau menimpa padding snippets/komponen, pakai `px-*`/`py-*`, bukan `p-*`; dan selalu
buktikan offset-nya di `dist/assets/index-*.css`, jangan berasumsi.

Dark variant juga menang dari snippet selama call-site memakai utility core: diverifikasi
`.dark\:text-orange-400` 77021 > `.alert-warning:is(.dark *)` 30279 (banner warning GR memakai
`class="dark:text-orange-400"` supaya warna dark lama tidak berubah — pola yang sama dipakai lagi di
`PurchaseReturnActionModals` dan `PurchaseReturnForm`), dan
`.dark\:bg-white\/\[0\.02\]` 75216 > `.form-readonly:is(.dark *)` 27504.

**Konvensi ukuran:** lebih suka token proyek (`text-theme-sm`, `text-theme-xs`) daripada
`text-sm`. `--text-theme-sm` kebetulan sama nilainya dengan `text-sm` bawaan, tetapi yang
kanonik adalah token proyek.

1. Blok lama `html.dark [role="dialog"] { background-color: … !important }` (sisa tema
   FullCalendar) bisa mengunci warna panel `BaseModal` di dark mode. Blok itu sudah
   dihapus 2026-10-23 bersama sisa CSS FullCalendar yang mati — jangan dikembalikan.
2. ~~Blok template "Remove Date Icon" mengunci `display/opacity … !important` pada
   `input[type=date]::-webkit-calendar-picker-indicator` sehingga menang atas blok ERP.~~
   **Sudah dibereskan 2026-10-23**: blok itu dihapus dari `inputs.css`. Sekarang field
   bertanggal menampilkan indikator kalender native (di-invert lewat `filter: invert(1)` saat
   dark) dan seluruh field `cursor: pointer`. Alasan aman: aplikasi ini tidak punya
   `type="time"` sama sekali (tipe yang diekspos `BaseInput` hanya `date`), dan tidak ada
