## 2. Pemahaman Dua Artefak

### 2.1 `.kiro/steering/project-context-logger.md` — aturan global

- **Frontmatter:** `inclusion: always`. Ini satu-satunya file di folder `steering/`.
- **Targeting:** setiap AI — primary agent, sub-agent, model apa pun. Bukan hanya konvensi.
- **Sifat aturan:** normatif, tidak opsional ("WAJIB dipatuhi"), dengan pengecualian eksplisit.
- **Isi fungsional:**
  1. **Trigger pencatatan** — setelah menganalisa kode, mengubah kode, menjalankan verifikasi penting,
     atau mengambil keputusan desain.
  2. **Pengecualian** — basa-basi / klarifikasi singkat tidak wajib.
  3. **Lokasi & nama file** — `knowledge-base/project-context/YYYY-MM-DD.md`, satu file per hari.
  4. **Semantik append** — masih hari sama maka append; ganti hari maka file baru; jangan sentuh file
     hari sebelumnya.
  5. **Format entri** — `## [HH:MM] Judul — <model/agent>` + narasi + 4 baris metadata (File yang
     diubah / Hasil verifikasi / Keputusan penting / Langkah berikutnya).
  6. **Bahasa** — Bahasa Indonesia, ringkas tapi cukup detail agar AI lain bisa melanjutkan.
  7. **Header file harian** — template wajib saat membuat file baru.
  8. **Alur 3 langkah** — baca konteks hari ini + hari sebelumnya sebelum kerja, kerjakan, lalu append.
  9. **Larangan** — jangan ubah/hapus entri lama; jangan pindahkan ke tanggal salah; jangan lewatkan
     pencatatan setelah mengubah kode.
- **Kapan aktif:** sejak file di-inject, yaitu **selama** sesi — bukan pada titik tertentu dalam alur.
- **Ukuran:** 3.528 byte, kira-kira **950 token** (estimasi; lihat §9.2 untuk implikasi biaya).

### 2.2 `.kiro/hooks/qa-after-dev.json.disabled` — gate post-development

- **Trigger:** `Stop`. Dalam Kiro ini berarti "agen berhenti / selesai satu giliran".
- **Action:** `type: "agent"` → **menyuntik sebuah prompt** ke sesi, bukan menjalankan perintah.
- **Teks prompt** (dengan koreksi `frontend/**` → `frontend-tailadmin/**`):

  > Sesi eksekusi baru saja selesai. JIKA pada sesi ini ada pengembangan atau perubahan kode backend
  > (di `backend/**`) atau frontend (di `frontend-tailadmin/**`) — bukan sekadar analisa, obrolan, atau
  > perubahan dokumen/knowledge-base — maka lakukan verifikasi QA sebelum menganggap tugas benar-benar
  > selesai:
  > 1. Delegasikan verifikasi ke sub-agent `qa-engineer` dengan menyebutkan scope perubahan dan gate
  >    mana yang perlu dijalankan.
  > 2. Backend: `npx tsc --noEmit` + unit test lulus.
  > 3. Frontend: type-check/build lulus sesuai stack yang disepakati.
  > 4. Tunggu Laporan QA (status tiap gate + verdict DONE/NOT DONE) sebelum menyatakan selesai ke user.
  >
  > Jika sesi ini TIDAK menyentuh kode backend/frontend (mis. hanya analisa, perencanaan, atau update
  > dokumen), ABAIKAN pengingat ini dan jangan menjalankan QA.

- **Dua kondisi yang wajib bercabang:** (a) ada perubahan kode → wajib QA; (b) tidak ada → **diam**.
  Inilah yang membuatnya sebuah *gerbang bersyarat*, bukan sekadar pengingat yangbero-noise.
- **Status aktif: ✅ AKTIF — dikonfirmasi user 2026-10-06 (D4).** Analisa awal
  menyimpulkan "tidak pasti" karena suffix `.disabled`; itu **SALAH sebagai
  kesimpulan**. Hook **memang menjalankan QA end-to-end** setelah development
  selesai; yang dilakukan hanya **menonaktifkannya sementara untuk menghemat
  token**. Koreksi ini penting karena mengubah gate QA dari "opsional" menjadi
  **komponen wajib** (§5.2, §6.6.2).
- **BUG yang harus diperbaiki saat transliterasi:** teks masih menunjuk `frontend/**`, yang menurut
  **ADR 54 §2.2 = DEPRECATED**. Harus `frontend-tailadmin/**`.

### 2.3 Bagaimana keduanya saling terkait

```
┌─ steering/project-context-logger.md ───────────────┐
│  SALURAN KONTINUITAS (continuity)                  │
│  Aktif pada SETIAP SESI, sejak awal, ke SEMUA agent.│
│  Output: knowledge-base/project-context/YYYY-MM-DD  │
└────────────────────┬──────────────────────────────┘
                     │ menghasilkan jejak perubahan
                     ▼
┌─ hooks/qa-after-dev.json (trigger: Stop) ───────────┐
│  GERBANG KUALITAS (quality gate)                    │
│  Aktif pada SATU TITIK: akhir giliran.              │
│  Hanya sesi root. Hanya kalau ada diff kode.        │
│  Output: Laporan QA (doc 21/22)                     │
└────────────────────────────────────────────────────┘
```

Steering = **wajib di semua titik**. Hook = **wajib di satu titik**. Keduanya tidak tumpang tindih;
menghapus salah satunya menghapus dua kontrol yang berbeda.

Keduanya juga saling melengkapi pada level output: entri `project-context` memuat baris "File yang diubah"
dan "Hasil verifikasi" — dan baris itulah yang jadi bukti untuk memutuskan apakah hook perlu menyalakan QA.

### 3.1 Hook API plugin — dari `@opencode-ai/plugin@1.18.34` (`dist/index.d.ts`)

Semua nama di bawah **terkonfirmasi langsung dari type definition lokal** di
`.opencode/node_modules/@opencode-ai/plugin/dist/index.d.ts` — bukan dari ingatan:

| Hook | Bentuk signature (ringkas) |
|---|---|
| `event` | `(input: { event: Event })` |
| `config` | `(input: Config)` — mutasi in-place |
| `tool` | `{ [name]: ToolDefinition }` — menambah tool custom |
| `chat.message` | `(input: { sessionID, agent?, model?, messageID?, variant? }, output: { message, parts })` |
| `chat.params` | `output: { temperature, topP, topK, maxOutputTokens, options }` |
| `chat.headers` | `output: { headers }` |
| `permission.ask` | `(input: Permission, output: { status: "ask" \| "deny" \| "allow" })` |

| `tool.execute.before` | `(input: { tool, sessionID, callID }, output: { args })` |
| `tool.execute.after` | `(input: { tool, sessionID, callID, args }, output: { title, output, metadata })` |

**Penting: tidak ada hook bernama `Stop`.** Trigger `Stop` milik Kiro tidak punya padanan bernama sama.

### 3.2 Lokasi direktori plugin — koreksi terhadap premis

Dokumen resmi `/docs/plugins/` menyatakan:

- Direktori plugin lokal: **`.opencode/plugins/`** (jamak) dan `~/.config/opencode/plugins/`.
  **BUKAN** `.opencode/plugin/` (tunggal). Premis awal salah pada titik ini.
- File JS/TS di direktori tersebut **dimuat otomatis saat startup** — **tidak perlu** entri `plugin`
  di `opencode.json`.
- Load order: config global → config project → direktori plugin global → direktori plugin project.
- Untuk memakai dependency npm, taruh `package.json` di direktori config; opencode menjalankan
  `bun install` saat startup.

### 3.3 `AGENTS.md` dan `instructions:` — perilaku terverifikasi

Dari `/docs/rules/` dan source `packages/opencode/src/session/instruction.ts`:

- `AGENTS.md` di root project **ditemukan otomatis** (naik dari direktori kerja sampai worktree root).
- Fallback berurutan: `AGENTS.md` → `CLAUDE.md` → `CONTEXT.md` (deprecated). Bisa dimatikan dengan
  `OPENCODE_DISABLE_CLAUDE_CODE=1`.
- Taksonomi global: `~/.config/opencode/AGENTS.md` (global) > `AGENTS.md` (project) >
  `~/.claude/CLAUDE.md`.
- `instructions: ["<path | glob | url>"]` di `opencode.json`. Path relatif di-resolve via `globUp` dari
  direktori kerja; URL remote di-fetch dengan **timeout 5 detik**.
- **Konten di-inject sebagai** `Instructions from: <absolute path>\n<isi file>` — satu elemen array per file.
- **`instructions` tidak menimpa `AGENTS.md`** — keduanya **digabung** ke array system yang sama.

### 3.4 Bukti propagasi ke sub-agent (KRITIS untuk keputusan §5.1)

Dari `packages/opencode/src/session/prompt.ts`, loop utama sekitar baris 1257–1269:

```ts
const [skills, env, instructions, mcpInstructions, modelMsgs] = yield* Effect.all([
  sys.skills(agent),
  sys.environment(model),
  instruction.system().pipe(Effect.orDie),   // <-- AGENTS.md + instructions
  sys.mcp(agent, session.permission),
  MessageV2.toModelMessagesEffect(msgs, model),
])
const system = [
  ...env,
  ...instructions,                            // <-- selalu ada di sini
  ...(mcpInstructions ? [mcpInstructions] : []),
  ...(skills ? [skills] : []),
]
```

`instruction.system()` bergantung pada `InstanceState.context` (`directory` / `worktree`) — **bukan** pada
`sessionID`. Karena setiap sub-agent adalah sesi anak yang melewati loop prompt yang sama dengan `directory`
yang sama, **`instructions` / `AGENTS.md` otomatis berlaku untuk primary agent, sub-agent, dan agent
tersembunyi** (`compaction`, `summary`, `title`).

Tingkat keyakinan: **TINGGI** (berdasar source, bukan dokumentasi). Tetap perlu 1× konfirmasi empiris
saat implementasi.

### 3.5 Sinyal "sesi ini menyentuh kode" — `session.diff`

opencode melacak diff file per sesi secara native. Ini ditemukan lewat `@opencode-ai/sdk@1.18.34`:

- `client.session.diff({ path: { id } })` → `Array<FileDiff>` dengan
  `{ file, before, after, additions, deletions }`.
- `client.session.children({ path: { id } })` → daftar sesi anak (untuk agregasi diff sub-agent).
- `client.session.get({ path: { id } })` → `Session` dengan `parentID?: string`,
  `time: { created, updated, compacting? }`.
- `client.session.promptAsync({ path: { id }, body: { parts, agent?, system?, model?, noReply? } })`
  → menyuntik pesan user **tanpa menunggu** selesai (non-blocking).

Ini adalah **keunggulan nyata** atas hook Kiro: hook Kiro hanya bisa menebak "apakah sesi ini
tampaknya menyentuh `backend/**`" dari isi percakapan; di opencode kita bisa **bertanya langsung**
ke sumber kebenaran diff.

### 3.6 Mekanisme opencode yang TIDAK ada (gap keras)

| Yang tidak ada di opencode | Dampak pada migrasi |
|---|---|
| Hook bernama `Stop` | Harus dipetakan ke `event` + `type === "session.idle"` |
| Field `inclusion: always` | Harus lewat `instructions` / `AGENTS.md` / `experimental.chat.system.transform` |
| `resources:` pada agent (auto-inject file) | **Tidak ada padanan sama sekali.** Harus lewat `instructions` global, atau menyalin isi ke body prompt agent |
| `action: { type: "agent", prompt }` (suntik prompt) | Harus lewat `client.session.promptAsync()` di dalam plugin — tidak bisa deklaratif |
| `toolsSettings.subagent.trustedAgents` | Tidak ada; padanan terdekat `permission.task` berbasis glob |
| Sifat "diam kalau tidak ada perubahan" pada trigger | Harus diimplementasikan manual di dalam plugin |
| Scope per-hook (hanya root agent) | Harus diimplementasikan manual (filter `parentID`) |

**Jangan gunakan `experimental.hook.session_completed`:** field ini memang **ada** di type `Config`
(`@opencode-ai/sdk`), tapi bentuknya `{ command: string[], environment? }` — ia menjalankan **command
eksternal**, bukan menyuntik prompt ke model. Tidak bisa dipakai untuk gate QA. Dicatat agar tidak
dicoba ulang.

## 4. Penilaian Kesetaraan Semantik

### 4.1 `steering/project-context-logger.md` → `instructions:` di `opencode.json`

| Aspek | Kiro `inclusion: always` | opencode `instructions:` | Skor |
|---|---|---|---|
| Berlaku ke primary agent | Ya | Ya | 1:1 |
| Berlaku ke sub-agent | Ya | Ya (terbukti, §3.4) | 1:1 |
| Berlaku sejak awal sesi | Ya | Ya (system prompt, putaran 1) | 1:1 |
| Berlaku ke agent tersembunyi | Tidak pasti | Ya (efek samping) | netral |
| Bertahan setelah compaction | Ya | **Lebih baik** — dibaca ulang tiap turn | lebih baik |
| Bisa dipilih per-file | Tidak (hanya `always`) | Bisa (path / glob) | lebih baik |
| Framing ke model | Konten mentah | `Instructions from: <path>` + isi | kosmetik |
| Frontmatter ikut terkirim | Diconsume Kiro | **Tidak ada padanan** | perlu penyesuaian |
| Sifat "gagal keras" (fail-closed) | Ada | Tidak ada | gap |
| Biaya token | Sekali per injeksi | Tiap turn, ~950 token | gap |

**Kesetaraan semantik: ~90%. Layak transliterasi.**

**Yang TIDAK bisa ditransliterasi 1:1:**

1. **Frontmatter.** Kiro meng-*consume* `inclusion: always`. opencode tidak punya konsep itu, sehingga file
   yang sama persis akan terkirim ke model **termasuk blok YAML `---\ninclusion: always\n---` sebagai teks
   literal** — noisy dan sedikit menyesatkan. File yang dirujuk harus bebas frontmatter.
2. **Sifat wajib (fail-closed).** Kalau file hilang, aturan hilang diam-diam; tidak ada error. Kiro
   memberi indikator jelas bahwa steering aktif.
3. **Penegakan normatif.** opencode tidak menandai teks sebagai "WAJIB" secara struktural. Bobotnya
   bergantung pada penulisan prompt dan hierarki yang dibaca model.
4. **Biaya token berulang.** opencode membaca dan mengirim ulang isi instruksi pada **setiap** panggilan
   LLM (tidak ada cache di sisi ini). Untuk sesi panjang dengan banyak tool call, ~950 token diulang terus.
   Bandingkan Kiro: sekali injeksi per sesi.
5. **Duplikasi isi.** Jika aturan juga disalin ke body 4 file `.opencode/agents/*` (seperti sekarang),
   aturan muncul **dua kali** di konteks — token sia dan berpotensi saling mengulang secara membingungkan.

### 4.2 `hooks/qa-after-dev.json` → plugin `event` + `session.idle`

| Aspek | Kiro hook | opencode plugin | Skor |
|---|---|---|---|
| Trigger "sesi selesai" | `Stop` | `event` + `type === "session.idle"` | setara |
| Injeksi prompt ke sesi | `action.type = "agent"` | `client.session.promptAsync()` | setara |
| Syarat "hanya kalau ada perubahan kode" | Tidak bisa — hanya menebak | `client.session.diff()` | **lebih baik** |
| Hanya sesi root | Tidak diatur | Filter `parentID` | lebih ketat |
| Anti-loop | Tidak ada | Latch per-session + in-flight guard | tambahan |
| Sifat "diam kalau tidak ada perubahan" | Instruksi tekstual | Kode (fail-closed) | setara |
| Cakupan path frontend | Salah (`frontend/**` deprecated) | Diperbaiki ke `frontend-tailadmin/**` | fix |
| Sifat deklaratif | Ya | Tidak (harus imperatif) | gap |
| Prioritas/ordering hook | Ada (Kiro scheduler) | Tidak ada padanan | gap |

**Kesetaraan semantik: ~90%. Layak transliterasi.**

**Yang TIDAK bisa ditransliterasi 1:1:**

1. **Tidak ada hook `Stop` bernama.** `session.idle` adalah padanan terdekat. Ia juga menyala ketika model
   selesai karena alasan lain (mis. balasan teks biasa). Risiko praktis kecil karena gate ini dijaga
   `session.diff` — tapi tidak nol.
2. **`action.type = "agent"` tidak punya padanan deklaratif.** Harus memanggil API sesi dari dalam plugin.
   Konsekuensinya: logika, error handling, dan idempotensi menjadi **kode yang harus diuji**, bukan
   konfigurasi yang bisa ditinjau cepat.
3. **Sifat "diam" harus dipaksakan.** Kiro mempercayai model untuk membaca kalimat "ABAIKAN". Di opencode
   kita bisa menulis kode dan **tidak mengirim apa pun** bila `session.diff` kosong — secara semantik
   **lebih kuat**, tapi mengubah sifat kontrol dari "instruktif" jadi "operasional".
4. **Tidak ada prioritas antar-hook.** Kalau nanti ada plugin lain, urutan tidak bisa dikonfigurasi.

## 5. Keputusan yang Diusulkan

### 5.1 Steering — perbandingan tiga opsi

#### Opsi (a) `instructions:` di `opencode.json`

```json
{ "instructions": ["knowledge-base/56.project-context-logger.md"] }
```

- **Plus:** terbukti berlaku ke sub-agent (§3.4); nol kode; idempoten secara konstruksi (opencode
  menaruh path dalam `Set`, jadi tidak ada duplikasi); dibaca ulang tiap turn sehingga **bertahan otomatis
  melewati compaction**; ter-version di git; mudah direview.
- **Minus:** menyasar **semua** sesi termasuk agent tersembunyi (`compaction`, `summary`, `title`) —
  ~950 token sia per pemanggilan pada 3 agent yang tidak butuh aturan ini; tidak ada fail-closed;
  instruksi dibaca ulang tiap turn.
- **Mitigasi biaya:** pengenaan pada agent tersembunyi bisa diabaikan — 3 agent tersebut berjalan
  sangat jarang dibanding turn utama.

#### Opsi (b) `AGENTS.md` di root

- **Plus:** format yang paling standar & portable (Claude Code, Cursor, dan tooling lain ikut baca);
  otomatis ditemukan tanpa menyentuh `opencode.json`; digabung dengan `instructions`.
- **Minus:** root `AGENTS.md` akan menjadi **racun kontekstual** — ia juga dibaca manusia dan AI lain
  yang tidak memakai opencode, dan isinya ikut terkirim mentah. Repository ini belum punya `AGENTS.md`
  sama sekali; memulai sekarang berarti memulai dari file yang akan terus tumbuh tanpa owner.
  Selain itu `AGENTS.md` root **tidak bisa saklar** — tidak ada cara menonaktifkannya per-konteks.

#### Opsi (c) Plugin `experimental.chat.system.transform`

- **Plus:** bisa menyuntik berdasarkan `sessionID`; bisa idempoten secara eksplisit; bisa di-toggle lewat
  environment variable; bisa Menyaring per-agent (dengan mencari tahu agent dari session).
- **Minus:** **tidak ada `agent` di input hook** — hanya `{ sessionID?, model }`. Untuk menyaring per-agent
  harus memanggil `client.session.get()` **pada setiap panggilan LLM** (latency + satu network call per
  turn per sesi). Biaya itu bertentangan dengan tujuan "hemat konteks", dan membuat mekanisme ini lebih
  rapuh — bukan lebih kuat — dibanding opsi (a).

#### Keputusan: **OPSI (a) — `instructions:` di `opencode.json`** → ✅ **DIPUTUSKAN USER (D5)**

> **D5 (2026-10-06):** user **setuju** memakai `instructions:` di `opencode.json`
> untuk aturan logger — bukan plugin. Plugin tetap dipakai untuk **gate QA**
> karena gate memang butuh trigger runtime.

Alasan:

1. **Coverage paling penting** — berlaku ke sub-agent — sudah terbukti dari source (§3.4).
   Opsi (c) belum tentu benar karena harus menebak agent per session.
2. **Idempotensi gratis.** `Instruction.systemPaths()` memakai `Set<string>`, jadi entry yang sama tidak
   pernah ter-inject dua kali. Plugin harus menulis idempotensi sendiri.
3. **Nol beban pemeliharaan.** Tidak ada kode, tidak ada type-check, tidak ada kegagalan runtime.
   Aturan ini bersifat normatif dan jarang berubah — bukan jenis aturan yang butuh logika runtime.
4. **Bertahan melewati compaction secara gratis.** Karena dibaca tiap turn, aturannya tidak hilang
   seperti prompt yang tertulis di dalam percakapan.
5. **Opsi (c) disimpan** sebagai **escape hatch** untuk kasus yang benar-benar butuh kondisi runtime, dan
   **bukan** sebagai mekanisme utama.

> Catatan jujur: opsi (c) adalah satu-satunya yang bisa menegakkan "fail-closed" secara aktif. Itu
> memang satu keunggulan nyata. Diterima sebagai gap (§4.1 butir 2).

#### Lokasi file kanonik untuk isi aturan

### 5.2 Hook QA-after-dev — pemilihan hook

> ⚠️ **D4 (2026-10-06) menaikkan prioritas bagian ini dari "opsional" menjadi
> WAJIB.** Hook Kiro terbukti **memang berjalan** (QA end-to-end pasca-dev) dan
> hanya dinonaktifkan sementara untuk hemat token. Plugin di §6.6.2 karena itu
> bukan tambahan — ia adalah **pemindahan kontrol yang nyata**, dan harus bisa
> dinyalakan/matikan dengan satu langkah.

| Kandidat | Verdict | Alasan |
|---|---|---|
| `event` + `session.idle` | **DIPILIH** | Padanan semantik terdekat dari `Stop`. opencode mengirim event ini saat sesi selesai satu giliran. Membership dijamin: `EventSessionIdle` ada di `@opencode-ai/sdk` dan `session.idle` ada di daftar event resmi. Menyediakan `sessionID` sehingga gate bisa scoped. |
| `experimental.chat.system.transform` | ditolak | Timing salah: hook ini menyala **sebelum** model bekerja, bukan setelah. Akan menyuntik pengingat "sesi selesai" ke konteks yang sedang berjalan — membingungkan dan boros. |
| `tool.execute.after` | ditolak sebagai trigger utama | Terlalu granular — menyala per pemanggilan tool, bukan per akhir giliran. Hanya berguna sebagai **sinyal cadangan**. |
| `experimental.session.compacting` | ditolak | menyasar konteks yang sudah penuh, bukan akhir pekerjaan. |
| `experimental.hook.session_completed` (config) | ditolak | Menjalankan command eksternal; tidak bisa menyuntik prompt (§3.6). |
| `command.execute.before` | ditolak | Hanya saat user menjalankan command, bukan tiap akhir giliran. |
| `chat.message` | ditolak sebagai trigger | Menyala saat pesan **masuk**, bukan saat selesai. Justru berguna sebagai **re-arm latch** (§6.4). |

**Deteksi "sesi ini menyentuh kode":** gunakan `client.session.diff()` sebagai sinyal utama, bukan
keyword matching seperti Kiro. Konsekuensinya: gate jauh lebih akurat, dan memenuhi prinsip fail-closed
(tidak ada diff di bawah code path berarti tidak ada nudge).

### 6.3 `.opencode/plugins/erp-qa-gate.ts` — draft final (TypeScript lengkap)

**Catatan lokasi:** folder **`.opencode/plugins/`** (jamak). Tidak perlu entri `plugin` di
`opencode.json` — dimuat otomatis. Extension `.ts` didukung resmi.

**Ringkasan desain hook yang dipakai:**

| Hook | Peran dalam plugin ini |
|---|---|
| `event` (`session.idle`) | **Trigger utama.** Menjalankan gate. |
| `chat.message` | **Re-arm latch** + menandai sesi yang benar-benar punya input user. |
| `tool.execute.after` | **Sinyal cadangan** mendeteksi file yang di-mutate, untuk kasus `session.diff` kosong. |

**Tiga lapis anti-loop (§6.4):** latch per-session, in-flight guard, dan re-arm hanya saat ada pesan user
baru.

```ts
/**
 * .opencode/plugins/erp-qa-gate.ts
 *
 * Transliterasi `.kiro/hooks/qa-after-dev.json.disabled`
 *   Kiro : trigger "Stop", action { type: "agent", prompt }
 *   opencode: event "session.idle" + client.session.promptAsync()
 *
 * Semantic equivalence: ~90%. Lihat knowledge-base/55 §4.2.
 *
 * Berbeda dari hook Kiro, gate ini decides sendiri secara fail-closed:
 * ia HANYA menyuntik reminder bila session.diff menunjukkan file yang
 * berubah berada di bawah salah satu codePaths. Tidak ada diff = diam.
 *
 * Differential utama vs hook Kiro:
 *   - Kiro menebak dari isi percakapan; di sini kita TANYA langsung ke
 *     client.session.diff() (opencode melacak diff per sesi secara native).
 *   - Cakupan path dikoreksi ke ADR 54: `frontend-tailadmin/**` = kanonik,
 *     `frontend/**` hanya dipantau untuk keamanan (deprecated).
 *   - Sifat "diam kalau tidak ada perubahan" dipaksakan oleh KODE, bukan
 *     oleh kepatuhan model membaca instruksi.
 */

import * as nodePath from "node:path"
import type { Plugin } from "@opencode-ai/plugin"

const LOG_SERVICE = "erp-qa-gate"

/** TTL latch: batas memori latch per sesi. */
const DEFAULT_LATCH_TTL_MS = 12 * 60 * 60 * 1000 // 12 jam

/**
 * Path yang diizinkan untuk memicu QA gate.
 * `frontend/` ikut dipantau untuk keamanan (ADR 54 §2.2 = DEPRECATED).
 */
const DEFAULT_CODE_PATHS = ["backend/", "frontend-tailadmin/", "frontend/"]

/** Tool yang mengubah isi file. Dipakai hanya sebagai sinyal cadangan. */
const MUTATING_TOOLS = new Set(["edit", "write", "patch", "apply_patch", "multiedit"])

const REMINDER = [
  "[erp-qa-gate]",
  "",
  "Sesi eksekusi baru saja selesai, dan opencode mendeteksi file KODE yang berubah pada sesi ini:",
  "",
  "- ${files}",
  "",
  "Sebelum menyatakan tugas selesai ke user, lakukan verifikasi QA:",
  "1. Delegasikan verifikasi ke sub-agent `qa-engineer`, sebutkan scope perubahan",
  "   (modul / endpoint / halaman yang tersentuh) dan gate mana yang perlu dijalankan",
  "   (lihat knowledge-base/21.definition-of-done.md dan",
  "   knowledge-base/22.repository-quality-gates.md).",
  "2. Perubahan backend (`backend/**`): pastikan `npx tsc --noEmit` dan unit test lulus.",
  "3. Perubahan frontend (`frontend-tailadmin/**`): pastikan type-check/build lulus",
  "   sesuai stack yang disepakati.",
  "4. Tunggu Laporan QA (status tiap gate + verdict DONE / NOT DONE) sebelum",
  "   menyatakan tugas selesai ke user.",
  "",
  "Jangan menjalankan QA kalau ternyata perubahan di atas hanya dokumentasi",
  "(knowledge-base/**) atau tidak relevan — dalam kasus itu, cukup sebut sekilas",
  "kenapa QA dilewati.",
].join("\n")

type Options = {
  enabled?: boolean
  codePaths?: string[]
  latchTtlMs?: number
  reminder?: string
}

export const ErpQaGate: Plugin = async ({ client, worktree }, rawOptions) => {
  const opts = {
    enabled: true,
    codePaths: DEFAULT_CODE_PATHS,
    latchTtlMs: DEFAULT_LATCH_TTL_MS,
    reminder: REMINDER,
    ...(rawOptions as Options | undefined),
  }

  // Kill switch environment (tanpa perlu edit file plugin).
  if (process.env.ERP_QA_GATE === "off" || process.env.ERP_QA_GATE === "0") {
    opts.enabled = false
  }

  /** sessionID -> timestamp nudge terakhir. Mencegah nudge berulang. */
  const latch = new Map<string, number>()
  /** sessionID yang sedang diproses gate. Mencegah re-entrancy. */
  const inFlight = new Set<string>()
  /** Sesi yang pernah menerima pesan user. Mencegah nudge pada sesi agent tersembunyi. */
  const userInitiated = new Set<string>()
  /** Sinyal cadangan: sessionID -> path relatif yang pernah di-mutate. */
  const touched = new Map<string, Set<string>>()

  const log = async (
    level: "debug" | "info" | "warn" | "error",
    message: string,
    extra?: Record<string, unknown>,
  ) => {
    try {
      await client.app.log({ body: { service: LOG_SERVICE, level, message, extra } })
    } catch {
      // Logging tidak boleh pernah menggagalkan sesi.
    }
  }

  /** Ubah path apa pun menjadi posix relatif terhadap worktree root. */
  const rel = (raw: string): string => {
    if (!raw || typeof raw !== "string") return ""
    const abs = nodePath.isAbsolute(raw) ? nodePath.resolve(raw) : nodePath.resolve(worktree, raw)
    const out = nodePath.relative(worktree, abs).split(nodePath.sep).join("/")
    return out.startsWith("./") ? out.slice(2) : out
  }

  const isCodePath = (repoRelative: string): boolean =>
    repoRelative !== "" && opts.codePaths.some((prefix) => repoRelative.startsWith(prefix))

  /** Kumpulkan ID sesi anak secara rekursif (sub-agent = sesi anak). */
  const collectSessionTree = async (rootID: string): Promise<string[]> => {
    const seen = new Set<string>([rootID])
    const queue = [rootID]
    while (queue.length > 0) {
      const current = queue.shift()!
      try {
        const res = await client.session.children({ path: { id: current } })
        for (const child of res.data ?? []) {
          if (!seen.has(child.id)) {
            seen.add(child.id)
            queue.push(child.id)
          }
        }
      } catch (err) {
        await log("debug", "session.children gagal; lanjut tanpa anak", {
          sessionID: current,
          error: String(err),
        })
      }
    }
    return [...seen]
  }

  /**
   * File kode yang berubah di seluruh pohon sesi (root + sub-agent).
   * Sinyal utama = session.diff. Sinyal cadangan = touched (dari tool.execute.after).
   */
  const collectTouchedCodeFiles = async (rootID: string): Promise<string[]> => {
    const tree = await collectSessionTree(rootID)
    const hits = new Set<string>()

    for (const id of tree) {
      try {
        const res = await client.session.diff({ path: { id } })
        for (const d of res.data ?? []) {
          const r = rel(d.file)
          if (isCodePath(r)) hits.add(r)
        }
      } catch (err) {
        await log("debug", "session.diff gagal; andalkan sinyal tool", {
          sessionID: id,
          error: String(err),
        })
      }

      for (const p of touched.get(id) ?? []) {
        if (isCodePath(p)) hits.add(p)
      }
    }
    return [...hits].sort()
  }

  /** Buang entri latch yang sudah kedaluwarsa agar Map tidak tumbuh tanpa batas. */
  const pruneLatch = (now: number) => {
    for (const [id, at] of latch) {
      if (now - at > opts.latchTtlMs) latch.delete(id)
    }
  }

  return {
    // (1) Re-arm latch saat user mengirim pesan baru.
    //     Ini yang membuat gate berlaku "sekali per akhir giliran", bukan sekali
    //     per hidup proses opencode.
    "chat.message": async (input) => {
      try {
        userInitiated.add(input.sessionID)
        latch.delete(input.sessionID)
      } catch (err) {
        await log("warn", "chat.message gagal", { error: String(err) })
      }
    },

    // (2) Sinyal cadangan: catat file yang di-mutate tool.
    //     Dipakai hanya bila session.diff tidak tersedia / kosong.
    "tool.execute.after": async (input) => {
      try {
        if (!MUTATING_TOOLS.has(input.tool)) return
        const candidates = [
          (input.args as any)?.filePath,
          (input.args as any)?.path,
          (input.args as any)?.file,
          ...(((input.args as any)?.files as string[] | undefined) ?? []),
        ]
        for (const candidate of candidates) {
          if (typeof candidate !== "string" || candidate.length === 0) continue
          const r = rel(candidate)
          if (!isCodePath(r)) continue
          const set = touched.get(input.sessionID) ?? new Set<string>()
          set.add(r)
          touched.set(input.sessionID, set)
        }
      } catch (err) {
        await log("debug", "tool.execute.after gagal", { error: String(err) })
      }
    },

    // (3) Trigger utama: padanan terdekat dari Kiro "Stop".
    event: async ({ event }) => {
      if (!opts.enabled) return
      if (event.type !== "session.idle") return

      const sessionID = (event as any).properties?.sessionID as string | undefined
      if (!sessionID) return

      // --- Lapis anti-loop #1: in-flight guard -------------------------------
      if (inFlight.has(sessionID)) return
      inFlight.add(sessionID)

      try {
        // --- Lapis anti-loop #2: latch ---------------------------------------
        pruneLatch(Date.now())
        if (latch.has(sessionID)) return

        // Hanya sesi root. Sub-agent di-scope lewat parentID; nudge harus
        // jatuh di sesi tempat user bekerja (satu-satunya yang punya task tool).
        const self = await client.session.get({ path: { id: sessionID } })
        const session = self.data
        if (!session) return
        if (session.parentID) return

        // --- Lapis anti-loop #3: hanya sesi dengan input user nyata ----------
        // Ini menyaring agent tersembunyi (compaction / summary / title).
        if (!userInitiated.has(sessionID)) return

        // --- Syarat: ada perubahan kode ---------------------------------------
        const files = await collectTouchedCodeFiles(sessionID)
        if (files.length === 0) return

        // --- Set latch SEBELUM injeksi ----------------------------------------
        // Kalau injeksi gagal, latch tetap dipasang agar tidak retry-loop.
        latch.set(sessionID, Date.now())

        const body = opts.reminder.replace(
          "${files}",
          files.slice(0, 20).map((f) => `  - \`${f}\``).join("\n") +
            (files.length > 20 ? `\n  - ... dan ${files.length - 20} file lain` : ""),
        )

        const res = await client.session.promptAsync({
          path: { id: sessionID },
          body: { parts: [{ type: "text", text: body }] },
        })

        if (res.error) {
          await log("warn", "QA reminder gagal diinjeksi", {
            sessionID,
            files: files.length,
            error: String(res.error),
          })
          return
        }

        await log("info", "QA reminder diinjeksi", {
          sessionID,
          codeFiles: files.length,
        })
      } catch (err) {
        // Plugin TIDAK BOLEH melempar error; itu bisa merusak sesi.
        await log("error", "erp-qa-gate gagal total", { sessionID, error: String(err) })
      } finally {
        inFlight.delete(sessionID)
      }
    },
  }
}
```

**Catatan penting mengenai kode di atas:**

1. **`agent` sengaja TIDAK diisi** pada `promptAsync`. Agent `project-manager` ber-`mode: subagent`, jadi
   tidak bisa menjadi agent sebuah sesi root. Mengisi `agent` akan menggagalkan injeksi atau memaksa
   pergantian agent milik user. Karena itu teks reminder ditulis **netral terhadap agent**: "delegasikan ke
   `qa-engineer`" dibaca sebagai instruksi oleh agent yang punya `task: allow`.
2. **`promptAsync`, bukan `prompt`.** `prompt` menunggu sampai turn selesai — plugin akan memblokir hook
   `event` dan berisiko deadlock. `promptAsync` fire-and-forget.
3. **`session.parentID` difilter.** Tanpa ini, setiap sesi anak yang selesai akan memicu nudge sendiri,
   dan kita akan mendapat N reminder untuk satu pekerjaan.
4. **Sinyal `tool.execute.after` tetap dipasang** meski `session.diff` dianggap utama — ini belt-and-suspenders untuk kasus diff tidak terekam.
5. **Semua hook dibungkus `try/catch`.** Exception dari plugin hook dapat menggagalkansesi; tidak boleh
   dibiarkan lolos.

### 6.4 Strategi idempotensi (ringkas)

| Lapis | Mekanisme | Yang dicegah |
|---|---|---|
| 1. Latch per-session | `Map<sessionID, timestamp>`; unauthor punya 12 jam; di-`prune` berkala | Nudge berulang pada sesi yang sama |
| 2. Re-arm hanya saat pesan user baru | `chat.message` menghapus latch untuk sessionID itu | Gate mati permanen setelah turn pertama |
| 3. In-flight guard | `Set<sessionID>`, dibersihkan di `finally` | Re-entrancy saat dua event `session.idle` arrive bersamaan |
| 4. Latch dipasang SEBELUM injeksi | `latch.set(...)` mendahului `promptAsync` | Retry-loop kalau injeksi gagal |
| 5. Syarat diff | Hanya nudge bila ada file di bawah `codePaths` | Nudge pada sesi analisa/dokumentasi |
| 6. Filter root session | `parentID` harus `undefined` | Nudge pada sesi anak/sub-agent |
| 7. Filter input user | `userInitiated` harus berisi sessionID | Nudge pada `compaction`/`summary`/`title` |

## 6.5 Pemulihan Auto-Inject Dokumen Per Agent (D1 — konsekuensi `resources:`)

### 6.5.1 Masalah yang dipulihkan

`.kiro/agents/*.md` mendaftarkan blok `resources:` berisi 8–13 dokumen KB sebagai
`file://...`. Di Kiro, `resources` = **file yang otomatis dimuat ke konteks** setiap
kali agent aktif. `.opencode/agents/*.md` **membuang** blok itu dan menggantinya
dengan daftar path prosa di body prompt berjudul "Dokumen Rujukan (Baca Sesuai
Kebutuhan)".

Dampaknya (§1.4): auto-inject **hilang** — termasuk aturan
`project-context-logger` yang karena itu tidak pernah ter-inject ke sesi mana pun.
opencode **tidak punya padanan `resources:`**. Konvensi yang dipakai opencode
adalah `AGENTS.md` (global, tidak bisa per-agent) dan `instructions:` di config
(juga global). Keduanya **tidak bisa dibedakan per agent**.

**Keputusan D1 + realitas mekanisme:** auto-inject per-agent tidak bisa
dipulihkan sebagai mekanisme *injeksi*. Yang dipulihkan adalah **kewajiban
eksplisit**: tiap agent diberi blok "Dokumen Rujukan WAJIB" di body prompt-nya,
dengan instruksi membacanya di awal sesi. Ini secara fungsional setara untuk
tujuan governance (agent tahu dokumen mana yang mengikat), walau berbeda sifat:
**read-on-demand, bukan auto-inject.**

Konsekuensi yang harus dicatat jujur: pemulihannya **bukan** kembalinya auto-inject.
Biaya token 30–60k per sub-agent **tidak** kembali (dan ini memang yang
diinginkan), tetapi kepatuhan kini bergantung pada model benar-benar membaca —
jadi aturan harus ditulis eksplisit di prompt, bukan diharapkan otomatis.

```ts
/**
 * .opencode/plugins/erp-qa-gate.ts
 *
 * Transliterasi `.kiro/hooks/qa-after-dev.json` (hook Kiro yang MEMANG AKTIF,
 * hanya dinonaktifkan sementara — koreksi atas asumsi lama di ADR 55 §1.1).
 *
 *   Kiro     : trigger "Stop"      -> action { type: "agent", prompt }
 *   opencode : event "session.idle" -> client.session.promptAsync()
 *
 * Kesetaraan semantik ~90% — lihat knowledge-base/55 §4.2.
 *
 * Perbedaan yang disengaja (lebih ketat dari hook Kiro):
 *   - Deteksi perubahan pakai `client.session.diff()` + agregasi
 *     `session.children()` — BUKAN menebak dari isi percakapan.
 *   - "Diam kalau tidak ada perubahan" dipaksakan oleh KODE, bukan kepatuhan
 *     model membaca instruksi.
 *   - Hanya sesi ROOT yang dinudge (filter `parentID`) sehingga satu rangkaian
 *     Task = satu reminder, bukan satu per sub-agent.
 *   - Gagal mendeteksi perubahan = BLOCKED, bukan diam (fail-closed).
 *
 * Plugin ini TIDAK PERNAH menulis/mengubah file apa pun. `backend/**` dan
 * `frontend-tailadmin/**` hanya dibaca lewat session.diff — tidak pernah ditulis.
 *
 * Token type reference: @opencode-ai/plugin@1.18.34 + @opencode-ai/sdk@1.18.34
 */

import * as nodePath from "node:path"
import type { Plugin } from "@opencode-ai/plugin"

// ============================================================================
// SAKELAR UTAMA — ubah nilai `true` <-> `false` di sini untuk on/off permanen.
// Untuk on/off sementara tanpa edit file, set environment variable
// ERP_QA_GATE=off (atau =on). Env var selalu menang atas konstanta ini.
// ============================================================================
const ENABLED = true

const ENV_KEY = "ERP_QA_GATE"
const OFF_VALUES = new Set(["off", "0", "false", "no", "disabled"])
const ON_VALUES = new Set(["on", "1", "true", "yes", "enabled"])

/** Path yang memicu QA gate. `frontend/` ikut dipantau untuk keamanan (ADR 54). */
const DEFAULT_CODE_PATHS = ["backend/", "frontend-tailadmin/", "frontend/"]

/** TTL latch per sesi (anti double-nudge). */
const DEFAULT_LATCH_TTL_MS = 12 * 60 * 60 * 1000

/** Batas file yang ditampilkan di reminder. */
const MAX_LISTED_FILES = 20

/** Tool yang mengubah isi file (sinyal cadangan). */
const MUTATING_TOOLS = new Set(["write", "edit", "patch", "multiedit"])

const LOG_SERVICE = "erp-qa-gate"

/** Penanda unik untuk mendeteksi echo prompt kita sendiri (anti-loop §6.6.4). */
const MARKER = "[erp-qa-gate]"

const REMINDER_TEMPLATE = [
  MARKER,
  "",
  "Sesi eksekusi baru saja selesai, dan opencode mendeteksi file KODE yang berubah",
  "pada sesi ini:",
  "",
  "${files}",
  "",
  "Sebelum menyatakan tugas selesai ke user, lakukan verifikasi QA:",
  "1. Delegasikan verifikasi ke sub-agent `qa-engineer`, sebutkan scope perubahan",
  "   (modul / endpoint / halaman yang tersentuh) dan gate mana yang perlu",
  "   dijalankan (lihat knowledge-base/21.definition-of-done.md dan",
  "   knowledge-base/22.repository-quality-gates.md).",
  "2. Perubahan backend (`backend/**`): pastikan `npx tsc --noEmit` dan unit test lulus.",
  "3. Perubahan frontend (`frontend-tailadmin/**`): pastikan type-check/build lulus",
  "   sesuai stack yang disepakati.",
  "4. Tunggu Laporan QA (status tiap gate + verdict DONE / NOT DONE) sebelum",
  "   menyatakan tugas selesai ke user.",
  "",
  "Kalau ternyata perubahan di atas hanya dokumentasi (`knowledge-base/**`) atau",
  "tidak relevan, sebutkan singkat alasan QA dilewati — jangan diamkan.",
].join("\n")

const BLOCKED_TEMPLATE = [
  MARKER,
  "",
  "GATE QA: BLOCKED.",
  "",
  "opencode tidak berhasil membaca daftar file yang berubah pada sesi ini",
  "(endpoint session.diff / session.children tidak tersedia atau error).",
  "Karena itu gate tidak bisa memutuskan sendiri apakah ada perubahan kode.",
  "",
  "Tindakan yang WAJIB dilakukan:",
  "1. Jalankan `git status --short` dan `git diff --stat` untuk melihat sendiri",
  "   apa yang berubah di sesi ini.",
  "2. Kalau ada perubahan di `backend/**` atau `frontend-tailadmin/**`,",
  "   delegasikan verifikasi ke sub-agent `qa-engineer` sebelum menyatakan selesai.",
  "3. Kalau tidak ada perubahan kode, sebutkan singkat bahwa gate ter-blockir",
  "   namun tidak ada kode yang tersentuh.",
].join("\n")

type Options = {
  enabled?: boolean
  codePaths?: string[]
  latchTtlMs?: number
  reminder?: string
  blockedNotice?: string
}

/** Baca env var sakelar. Env var menang atas konstanta ENABLED. */
const envToggle = (): boolean | undefined => {
  const raw = (process.env[ENV_KEY] ?? "").trim().toLowerCase()
  if (raw === "") return undefined
  if (OFF_VALUES.has(raw)) return false
  if (ON_VALUES.has(raw)) return true
  return undefined
}

export const ErpQaGate: Plugin = async ({ client, worktree }, rawOptions) => {
  const opts = {
    enabled: ENABLED,
    codePaths: DEFAULT_CODE_PATHS,
    latchTtlMs: DEFAULT_LATCH_TTL_MS,
    reminder: REMINDER_TEMPLATE,
    blockedNotice: BLOCKED_TEMPLATE,
    ...(rawOptions as Options | undefined),
  }
  const env = envToggle()
  if (env !== undefined) opts.enabled = env

  /** sessionID -> timestamp nudge terakhir (anti double-nudge). */
  const latch = new Map<string, number>()
  /** sessionID yang sedang diproses (anti re-entrancy). */
  const inFlight = new Set<string>()
  /** Sesi yang pernah menerima pesan user (menyaring agent tersembunyi). */
  const userInitiated = new Set<string>()
  /** Sinyal cadangan: sessionID -> path relatif yang pernah di-mutate. */
  const touched = new Map<string, Set<string>>()

  const log = async (
    level: "debug" | "info" | "warn" | "error",
    message: string,
    extra?: Record<string, unknown>,
  ) => {
    try {
      await client.app.log({ body: { service: LOG_SERVICE, level, message, extra } })
    } catch {
      // Logging tidak boleh pernah menggagalkan sesi.
    }
  }

  /** Path apa pun -> posix relatif terhadap worktree root. */
  const rel = (raw: unknown): string => {
    if (typeof raw !== "string" || raw.length === 0) return ""
    const abs = nodePath.isAbsolute(raw) ? nodePath.resolve(raw) : nodePath.resolve(worktree, raw)
    const out = nodePath.relative(worktree, abs).split(nodePath.sep).join("/")
    return out.startsWith("./") ? out.slice(2) : out
  }

  const isCodePath = (p: string): boolean =>
    p !== "" && p !== ".." && !p.startsWith("../") && opts.codePaths.some((pre) => p.startsWith(pre))

  const prune = (now: number) => {
    for (const [id, at] of latch) if (now - at > opts.latchTtlMs) latch.delete(id)
    for (const [id, set] of touched) if (set.size === 0) touched.delete(id)
  }

  /** Kumpulkan seluruh sesi anak secara rekursif (sub-agent = sesi anak). */
  const collectSessionTree = async (rootID: string): Promise<string[]> => {
    const seen = new Set<string>([rootID])
    const queue = [rootID]
    while (queue.length > 0) {
      const current = queue.shift()!
      try {
        const res = await client.session.children({ path: { id: current } })
        for (const child of res.data ?? []) {
          if (!seen.has(child.id)) {
            seen.add(child.id)
            queue.push(child.id)
          }
        }
      } catch (err) {
        await log("warn", "session.children gagal", { sessionID: current, error: String(err) })
      }
    }
    return [...seen]
  }

  /**
   * File kode yang berubah di seluruh pohon sesi.
   * Sinyal utama = session.diff. Sinyal cadangan = touched (tool.execute.after).
   * Return `{ files, degraded }` — `degraded` = TIDAK ADA sinyal yang bisa
   * dibaca sama sekali → pemanggil harus fail-closed (BLOCKED), bukan diam.
   */
  const collectTouchedCodeFiles = async (
    rootID: string,
  ): Promise<{ files: string[]; degraded: boolean }> => {
    const tree = await collectSessionTree(rootID)
    const hits = new Set<string>()
    let diffSucceededAtLeastOnce = false
    let touchedSignal = false

    for (const id of tree) {
      try {
        const res = await client.session.diff({ path: { id } })
        diffSucceededAtLeastOnce = true
        for (const d of res.data ?? []) {
          const r = rel(d.file)
          if (isCodePath(r)) hits.add(r)
        }
      } catch (err) {
        await log("warn", "session.diff gagal", { sessionID: id, error: String(err) })
      }
      for (const p of touched.get(id) ?? []) {
        touchedSignal = true
        if (isCodePath(p)) hits.add(p)
      }
    }
    return { files: [...hits].sort(), degraded: !diffSucceededAtLeastOnce && !touchedSignal }
  }

  /**
   * Anti-loop lapis terakhir: apakah pesan user TERAKHIR di sesi ini adalah
   * prompt yang kita suntikkan sendiri? Kalau ya, JANGAN nudge lagi.
   * Ini menutup celah "restart opencode -> latch hilang -> echo -> nudge lagi".
   */
  const lastUserMessageIsOurs = async (sessionID: string): Promise<boolean> => {
    try {
      const res = await client.session.messages({ path: { id: sessionID }, query: { limit: 5 } })
      const msgs = res.data ?? []
      for (let i = msgs.length - 1; i >= 0; i--) {
        const entry = msgs[i]!
        if (entry?.info?.role !== "user") continue
        const text = (entry.parts ?? [])
          .map((p) => (p.type === "text" ? p.text : ""))
          .join("\n")
        return text.includes(MARKER)
      }
    } catch (err) {
      await log("debug", "session.messages gagal; lewati deteksi echo", { error: String(err) })
    }
    return false
  }

  const inject = async (sessionID: string, text: string): Promise<boolean> => {
    // Latch dipasang SEBELUM injeksi: kalau injeksi gagal, tidak ada retry-loop.
    latch.set(sessionID, Date.now())
    try {
      const res = await client.session.promptAsync({
        path: { id: sessionID },
        body: { parts: [{ type: "text", text }] },
      })
      if (res.error) {
        await log("error", "injeksi gagal", { sessionID, error: String(res.error) })
        return false
      }
      return true
    } catch (err) {
      await log("error", "injeksi melempar error", { sessionID, error: String(err) })
      return false
    }
  }

  if (!opts.enabled) {
    await log("info", "erp-qa-gate NON-AKTIF (sakelar off)", { env: process.env[ENV_KEY] ?? null })
  } else {
    await log("info", "erp-qa-gate aktif", {
      codePaths: opts.codePaths,
      env: process.env[ENV_KEY] ?? null,
    })
  }

  return {
    // (1) Re-arm latch saat user mengirim pesan baru. Inilah yang membuat gate
    //     berlaku "sekali per akhir giliran", bukan sekali per proses opencode.
    "chat.message": async (input) => {
      try {
        userInitiated.add(input.sessionID)
        latch.delete(input.sessionID)
      } catch (err) {
        await log("warn", "chat.message gagal", { error: String(err) })
      }
    },

    // (2) Sinyal cadangan: catat file yang di-mutate tool mutating.
    "tool.execute.after": async (input) => {
      try {
        if (!MUTATING_TOOLS.has(input.tool)) return
        const args = (input.args ?? {}) as Record<string, unknown>
        const candidates: unknown[] = [args.filePath, args.path, args.file, ...((args.files as string[]) ?? [])]
        const set = touched.get(input.sessionID) ?? new Set<string>()
        for (const candidate of candidates) {
          const r = rel(candidate)
          if (!isCodePath(r)) continue
          set.add(r)
        }
        if (set.size > 0) touched.set(input.sessionID, set)
      } catch (err) {
        await log("debug", "tool.execute.after gagal", { error: String(err) })
      }
    },

    // (3) Trigger utama: padanan terdekat dari Kiro "Stop".
    event: async ({ event }) => {
      if (!opts.enabled) return
      if (event.type !== "session.idle") return

      const sessionID = event.properties?.sessionID
      if (!sessionID) return

      // Lapis anti-loop #1: in-flight guard.
      if (inFlight.has(sessionID)) return
      inFlight.add(sessionID)

      try {
        // Lapis anti-loop #2: latch per sesi.
        const now = Date.now()
        prune(now)
        if (latch.has(sessionID)) return

        const self = await client.session.get({ path: { id: sessionID } })
        const session = self.data
        if (!session) return

        // Hanya sesi ROOT (sub-agent punya parentID).
        if (session.parentID) return

        // Hanya sesi dengan input user nyata (buang compaction/summary/title).
        if (!userInitiated.has(sessionID)) return

        // Lapis anti-loop #3: jangan memicu QA atas prompt QA kita sendiri.
        if (await lastUserMessageIsOurs(sessionID)) {
          await log("debug", "lewati: pesan terakhir adalah prompt gate sendiri", { sessionID })
          return
        }

        const { files, degraded } = await collectTouchedCodeFiles(sessionID)

        // FAIL-CLOSED: tidak bisa membaca sinyal APA PUN -> BLOCKED, jangan diam.
        if (degraded) {
          await log("error", "gate BLOCKED: session.diff & children tidak terbaca", { sessionID })
          await inject(sessionID, opts.blockedNotice)
          return
        }

        // Tidak ada perubahan kode -> diam (murni, tanpa injeksi apa pun).
        if (files.length === 0) return

        const listed =
          files.slice(0, MAX_LISTED_FILES).map((f) => `  - \`${f}\``).join("\n") +
          (files.length > MAX_LISTED_FILES
            ? `\n  - ... dan ${files.length - MAX_LISTED_FILES} file lain`
            : "")

        await inject(sessionID, opts.reminder.replace("${files}", listed))
        await log("info", "QA reminder diinjeksi", { sessionID, codeFiles: files.length })
      } catch (err) {
        // Plugin TIDAK BOLEH melempar error; itu bisa merusak sesi.
        await log("error", "erp-qa-gate gagal total", { sessionID, error: String(err) })
      } finally {
        inFlight.delete(sessionID)
      }
    },
  }
}
```

**Catatan kunci mengenai kode di atas:**

1. **`agent` sengaja tidak diisi** pada `promptAsync`. Agent `project-manager`
   ber-`mode: subagent`, jadi tidak bisa menjadi agent sebuah sesi root;
   mengisinya akan gagal atau memaksa pergantian agent milik user. Teks reminder
   ditulis netral-agent: "delegasikan ke `qa-engineer`" dibaca sebagai instruksi
   oleh agent yang punya `task: allow`.
2. **`promptAsync`, bukan `prompt`.** `prompt` menunggu turn selesai → hook
   `event` terblokir dan berisiko deadlock. `promptAsync` fire-and-forget.
3. **Fail-closed (D4).** Kalau `session.diff` **dan** `session.children` sama
   sekali tidak terbaca, gate tidak pernah diam: ia menyuntik notice **BLOCKED**
   yang menyuruh agent memeriksa sendiri lewat `git` dan tetap mendelegasikan QA
   bila ada perubahan. Ini mencegah "hemat token" berubah jadi "gate buta".
4. **Anti-loop 5 lapis:** (1) in-flight guard, (2) latch per sesi + re-arm hanya
   saat `chat.message`, (3) latch dipasang sebelum injeksi, (4) filter
   `session.parentID === undefined`, (5) filter `userInitiated`. Plus lapis
   tambahan: `lastUserMessageIsOurs()` mendeteksi echo dari prompt gate sendiri
   via `session.messages` — menutup celah setelah restart opencode.
5. **Tidak menyentuh `backend/**`/`frontend-tailadmin/**`.** Plugin hanya
   membandingkan path string hasil `session.diff`; tidak ada operasi tulis
   sama sekali di seluruh file.
6. **`session.idle` juga menyala saat model selesai karena alasan lain** (mis.
   balasan teks biasa). Risiko praktis kecil karena dijaga lapis "hanya sesi root
   + hanya ada diff kode", tapi tidak nol.

## 9. Risiko & Edge Case

### 9.1 Risiko Konfigurasi

| # | Risiko | Mitigasi |
|---|---|---|
| R1 | **Injeksi prompt berulang** — `instructions` ditambahkan dua kali | opencode memakai `Set<string>` di `Instruction.systemPaths()` → secara konstruksi tidak mungkin duplikat. Plugin punya 5 lapis latch (§6.6.2 catatan 4). |
| R2 | **Loop tak terbatas** — nudge memicu turn → turn selesai → idle → nudge | Latch per-session + re-arm hanya saat pesan user baru + deteksi echo prompt sendiri (`lastUserMessageIsOurs`). Worst case: satu reminder per turn. opencode juga punya `permission.doom_loop` sebagai jaring pengaman tambahan. |
| R3 | **Gate salah sasaran** — nudge masuk ke sesi `compaction`/`summary`/`title` | Filter `userInitiated` (hanya sesi yang pernah dapat `chat.message`). Diverifikasi secara reasoning; perlu 1× uji. |
| R4 | **Nudge masuk ke sesi anak (sub-agent)** | Filter `session.parentID === undefined`. |
| R5 | **Reminder menyesatkan** — agent menganggap "tidak ada perubahan" lalu mengabaikannya | Teks reminder sudah menyertakan daftar file konkret. Kalau ternyata hanya dokumentasi, agent tetap diarahkan untuk menyebut singkat alasannya. Ini memindahkan beban penilaian dari kode ke model — **sengaja**, karena menebak maksud developer memang butuh model. |
| R6 | **`.kiro/steering/...` dihapus sementara `instructions` masih menunjuk ke sana** | `instructions` menunjuk doc 56 yang independen; stub `.kiro/` hanya untuk legibilitas manusia. Tidak ada failure mode. |
| R7 | **Plugin crash merusak sesi** | Semua hook dibungkus `try/catch`; tidak ada `throw`. `inject()` menelan error dan mencatatnya. |
| R8 | **Biaya token** — ~1.000 token × setiap panggilan LLM | Diterima. Alternatif (menyalin aturan ke body agent) justru boros karena duplikasi 4 file. |
| R9 | **`instructions` juga masuk ke agent tersembunyi** | 3 agent, jarang jalan. Diterima. |
| R10 | **Gate buta saat `session.diff` error** | **Fail-closed** (D4): kondisi `degraded` → suntik notice **BLOCKED** yang menyuruh agent cek `git` sendiri. Tidak pernah diam tanpa bukti. |
| R11 | **`.opencode/package.json` ter-ignore** | D6: hapus `package.json` dari `.opencode/.gitignore` (§6.6.6). Tanpa itu, versi plugin bisa berbeda antar mesin. |

### 9.2 Edge Case Konteks Hampir Penuh / Compaction

| Edge case | Perilaku | Catatan |
|---|---|---|
| Konteks hampir penuh, compaction terjadi | Aturan logger **bertahan** — `instruction.system()` dipanggil ulang tiap turn (§3.4). | Ini **kelebihan** dibanding aturan yang tertulis di dalam percakapan. Yang hilang saat compaction adalah isi percakapan, bukan data `session.diff` — itu data server-side, **tidak** hilang. ✅ |
| Plugin injeksi terjadi bersamaan dengan compaction | `promptAsync` tetap berjalan; turn berikutnya akan memuat post-compaction context | Risiko rendah; tidak ada operasi plugin yang menyentuh cache konteks. |
| Sesi sangat panjang (banyak sub-agent) | `collectSessionTree` bisa memanggil `session.children` cukup banyak | Dibatasi `seen` set; worst case O(jumlah subtree). Diterima untuk skala repo ini. |
| opencode restart di tengah sesi | Latch in-memory hilang → gate bisa nudge sekali lagi | Diterima. Alternatifnya persist latch ke disk, tapi menambah failure mode (file corrupt, race multi-instance). **Rekomendasi: biarkan in-memory**, tapi catat sebagai gap (§9.3). |

### 9.3 Gap yang Disengaja (tidak ditutup)

1. **Latch tidak persisten.** Restart opencode = satu reminder tambahan mungkin muncul. Diterima karena
   frekuensi rendah dan konsekuensinya kecil (satu reminder, bukan loop).
2. **Nudge hanya satu arah.** Gate tidak bisa memaksa QA benar-benar dijalankan — hanya mengingatkan.
   Tanggung jawab tetap di agent. Ini sama seperti Kiro; tidak ada mekanisme opencode untuk
   "block sampai QA pass".
3. **Sesi anak yang menjadi workspace aktif user** (user menekan `session_child_first` untuk masuk ke
   sub-agent) — root session sudah idle lebih dulu, jadi gate mungkin tidak menyala. Workaround

## 12. Ringkasan Eksekutif (versi final, ACCEPTED)

1. **Kedua aturan bisa diekspos ke opencode** — steering ≈ 90% setara, hook ≈ 90% setara.
2. **Steering → `instructions:` di `opencode.json`** (D5). Terbukti berlaku ke
   sub-agent; nol kode; idempoten secara konstruksi; bertahan melewati compaction.
   Dokumen kanoniknya: **`knowledge-base/56.project-context-logger.md`** (D2).
3. **Hook → plugin `.opencode/plugins/erp-qa-gate.ts`** (D4: **WAJIB**, karena hook
   Kiro memang terbukti bekerja), trigger `event` + `session.idle`, injeksi via
   `client.session.promptAsync()`, deteksi perubahan via `client.session.diff()` +
   agregasi `session.children()` (lebih akurat daripada Kiro yang hanya menebak),
   5 lapis anti-loop, **fail-closed** ke notice **BLOCKED** saat `session.diff`
   error, dan sakelar on/off (`ENABLED` + `ERP_QA_GATE`).
4. **`.opencode/` = single source of truth** (D1); Kiro tidak dipakai lagi (D3);
   `.kiro/agents/` **diarsipkan, tidak dihapus** tanpa persetujuan user.
5. **Gap yang tidak bisa ditutup:** tidak ada hook `Stop` bernama; `action.type =
   "agent"` tidak punya padanan deklaratif; `resources:` (auto-inject per agent)
   **tidak punya padanan sama sekali**; latch tidak persisten antar restart
   opencode; tidak ada fail-closed untuk aturan logger.
6. **Regresi yang ditemukan & ditangani:** konversi `.kiro/agents/` → `.opencode/agents/`
   diam-diam **kehilangan** auto-inject 8–13 dokumen KB per sub-agent. Dipulihkan
   sebagai **kewajiban eksplisit** lewat tabel Dokumen Rujukan Per Agent (§6.5)
   yang akan dituangkan ke body prompt tiap agent — bukan sebagai auto-inject.
7. **Asumsi lama yang dikoreksi (D4):** hook QA Kiro **tidak pernah diasumsikan
   tidak aktif**; user mengonfirmasi hook itu berjalan dan hanya dijeda
   sementara. Konsekuensinya, gate QA menjadi **komponen wajib**, bukan opsional.
