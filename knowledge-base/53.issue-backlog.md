## ISSUE-01 — ✅ Owner punya akses menu Roles (seharusnya hanya admin/super admin) · BE+FE · Prioritas: TINGGI (security) — FIXED
Setelah register company, OWNER memiliki akses ke menu **Roles**. Menurut User,
Roles seharusnya hanya untuk user admin / super admin.

**Solusi yang diterapkan (2026-10-24):**
- OWNER tidak lagi mendapat 8 permission system-administration: `user.read`, `user.manage`, `role.read`, `role.manage`, `permission.read`, `permission.manage`, `audit.read`, `auth.manage`
- `permissions.seed.ts`: OWNER sekarang mendapat explicit permission list (97 permissions), bukan sentinel `'ALL'`
- Migration 070: revoke 8 permission tsb dari semua OWNER role yang sudah ada
- `RegisterCompanyUseCase.ts`: hapus branch `permissions === 'ALL'`, semua role sekarang pakai explicit array
- Frontend sidebar & router guard sudah permission-gated (`user.read`/`role.read`), tidak perlu perubahan FE
- Verifikasi E2E: register company baru → login sebagai OWNER → JWT berisi 97 permission (0 system admin) → API `/users`, `/roles`, `/permissions` return 403

## ISSUE-04 — ✅ Status kadaluarsa salah (harus H+1, bukan hari ini) · BE+FE · Prioritas: SEDANG — FIXED
Perhitungan/penandaan status kadaluarsa dinilai salah — item dianggap kadaluarsa pada
hari-H, seharusnya H+1 (masih berlaku di hari kadaluarsa, kadaluarsa keesokan harinya).
- **Keputusan:** `expired_date` adalah hari TERAKHIR batch masih boleh dipakai; kedaluwarsa
  berlaku mulai H+1 (`expired_date < businessDate`, business date Asia/Jakarta). Dipakai oleh
  `classifyExpiry`/`toJakartaBusinessDate` (doc 27 aturan 14), Stock On Hand, POS availability,
  Batch & Expiry, dan Dashboard KPI.
- **Implementasi:** GET `/inventory/batches` mengirim `operationalStatus` turunan — batch `ACTIVE`
  yang lewat tanggal kedaluwarsa terbaca "Kedaluwarsa — tidak dapat digunakan" tanpa mengubah
  status lifecycle tersimpan, saldo stok, atau membuat mutasi. Kolom FE menjadi Sisa Stok Fisik /
  Status Operasional / Kondisi Kedaluwarsa dan filter status memakai `operationalStatus` agar
  konsisten dengan badge.
- **Batas:** picker Stock Adjustment & Stock Transfer tetap memakai filter `status` tersimpan,
  sehingga stok fisik kedaluwarsa/karantina tetap dapat dipilih untuk write-off manual.
