## ISSUE-01 — 🐞 Owner punya akses menu Roles (seharusnya hanya admin/super admin) · BE+FE · Prioritas: TINGGI (security)
Setelah register company, OWNER memiliki akses ke menu **Roles**. Menurut User,
Roles seharusnya hanya untuk user admin / super admin.
- **Catatan teknis (perlu diperiksa):** OWNER di-seed dengan permission `ALL`
  (sentinel) saat register company (lihat `permissions.seed.ts` DEFAULT_ROLES OWNER),
  sehingga otomatis mendapat `role.read`/`role.manage`. Perlu KEPUTUSAN BISNIS: apakah
  manajemen Role memang khusus SUPER_ADMIN (platform-level), bukan OWNER (tenant-level)?
  Bila ya, perlu mengeluarkan `role.*` (dan mungkin `permission.*`) dari grant OWNER +
  menyesuaikan sidebar gating. Berdampak ke RBAC — JANGAN diubah tanpa persetujuan User
  (doc 16). **Triase: perlu konfirmasi User soal batas kewenangan OWNER vs SUPER_ADMIN.**

## ISSUE-03 — 🐞 Stok waffle tidak berkurang setelah 2 kali transaksi · BE · Prioritas: TINGGI (korektness stok)
Stok waffle (atau bahannya) tidak berkurang setelah transaksi POS dibuat 2 kali.
- **Catatan teknis (perlu diperiksa):** POS Model A — produk MADE_TO_ORDER mengurangi
  stok BAHAN (backflush FEFO) saat PAID, bukan stok "waffle". Produk STOCK mengurangi
  stok produk sendiri. Perlu dicek: (a) apakah transaksi benar-benar sampai status PAID
  (bukan PENDING_PAYMENT)? (b) untuk waffle made-to-order, cek stok BAHAN (adonan/topping)
  di Stock On Hand/Ledger — mungkin yang dilihat User stok "waffle" yang memang tak dilacak;
  (c) cek apakah ada movement `SALE` tercatat di inventory_movements untuk order tsb;
  (d) kemungkinan bug idempotency/transaksi. **Triase: reproduksi + telusuri jalur pay()
  dan sales_consumptions untuk order yang dimaksud.**

## ISSUE-04 — 🐞 Status kadaluarsa salah (harus H+1, bukan hari ini) · BE · Prioritas: SEDANG
Perhitungan/penandaan status kadaluarsa dinilai salah — item dianggap kadaluarsa pada
hari-H, seharusnya H+1 (masih berlaku di hari kadaluarsa, kadaluarsa keesokan harinya).
- **Catatan teknis (perlu diperiksa):** cek logika klasifikasi expiry di inventory
  (`batchStatus`/`classifyExpiry`, doc 27). Perlu KEPUTUSAN: definisi "kadaluarsa" —
  apakah `expired_date` adalah hari TERAKHIR masih boleh dipakai (expired saat `today >
  expired_date`) atau hari pertama tidak boleh (expired saat `today >= expired_date`)?
  User minta H+1 → kemungkinan ganti `>=` menjadi `>`. Berdampak ke FEFO (exclude-expired)
  & monitoring. **Triase: konfirmasi definisi lalu sesuaikan perbandingan tanggal.**

## ISSUE-05 — ❓ Versi pada Recipe tidak bertambah (cara jadikan v2 dst) · BE+FE · Prioritas: SEDANG
Versi resep tidak bertambah; User tanya bagaimana mengubah ke v2 dan seterusnya.
- **Catatan teknis (perlu diperiksa):** cek apakah entity Recipe punya konsep `version`
  dan bagaimana lifecycle-nya (DRAFT/ACTIVE/ARCHIVED, satu ACTIVE per produk). Perlu
  KEPUTUSAN desain: apakah "versi baru" = buat recipe baru (archive lama → activate baru)
  dengan nomor versi auto-increment, atau edit in-place? Kemungkinan ini bukan bug tapi
  fitur versioning yang belum ada. **Triase: klarifikasi ekspektasi versioning resep dgn User.**

## ISSUE-06 — ✨ Datepicker: tombol "Hari Ini" + default hari ini · FE · Prioritas: SEDANG (UX, reusable)

## ISSUE-09 — ✨ Tampilkan sisa qty di list produk POS · FE(+BE?) · Prioritas: SEDANG
List produk di layar POS sebaiknya menampilkan sisa qty (stok tersedia) per produk.
- **Catatan teknis (perlu diperiksa):** untuk produk STOCK = sisa stok finished-goods;
  untuk produk MADE_TO_ORDER = kapasitas produksi (producible qty dari stok bahan, seperti
  panel producible di Production). Perlu KEPUTUSAN: tampilkan apa untuk made-to-order

  menambah data stok/producible. **Triase: tentukan definisi "sisa qty" per mode; cek endpoint.**
