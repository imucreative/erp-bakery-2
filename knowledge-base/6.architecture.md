# 11. Authorization Strategy

Use:

Permission-Based Authorization (RBAC v1.0)

Role Codes are stable, immutable technical identifiers (`OWNER`, `SUPERVISOR_OUTLET`, `ADMIN_GUDANG`, `PRODUKSI`, `KASIR`). Application authorization checks are performed entirely against user permission strings (e.g. `product.read`, `sales.manage`), never against Role Codes.

Rules:
- **Business Roles Only**: Every Role must represent an actual business position or operational function inside the Bakery ERP. Future roles include `PURCHASING_OFFICER`, `FINANCE_ADMIN`, `OPERATIONS_MANAGER`.
- **No Automatic "Other" Role**: Fallback or generic roles like `Other`, `Miscellaneous`, `General`, `Unknown`, or `Undefined` must never be introduced. If classification fails, request human clarification or recommend a new business role instead.
- **Role Creation**: New roles must satisfy: real business function, clear responsibility, defined permission set, documented in the Role & Permission Matrix, and approved.
- **Permission Classification Policy**:
  - The "Other" permission category/group is strictly prohibited and must never be generated or used.
  - Every permission must belong to exactly one of the 10 permission-enabled Business Modules:
    - `user.*`, `role.*`, `permission.*`, `audit.*` → **System Administration**
    - `outlet.*`, `warehouse.*`, `supplier.*`, `product-group.*`, `category.*`, `uom.*`, `product.*` → **Master Data**
    - `procurement.pr.*`, `procurement.po.*`, `procurement.gr.*` → **Procurement**
    - `inventory.*`, `stock-adjustment.*`, `stock-opname.*`, `stock-transfer.*`, `replenishment.*` → **Inventory**
    - `recipe.*`, `bom.*`, `production.*` → **Production**
    - `distribution.*`, `delivery-order.*`, `inter-outlet-transfer.*` → **Distribution**
    - `sales.*`, `shift.*`, `pos.*` → **Sales & POS**
    - `payment.*`, `expense.*`, `cashflow.*` → **Finance**
    - `dashboard.*`, `report.*` → **Reporting**
    - `setting.*`, `company.*` → **Settings**
  - If a new permission does not match any prefix, automatically determine the most appropriate business domain based on its prefix. If no domain fits, flag it for manual review.

Tables:

roles
permissions
role_permissions

Example:

OWNER role contains permissions:
* product.manage
* sales.manage
* uom.manage

# 14. FEFO Engine

FEFO implementation must exist in service layer.

Algorithm:

1. Select ACTIVE batches.
2. Exclude expired batches.
3. Sort by expired date ascending.
4. Consume nearest expired batch first.

Pseudo Code:

SELECT batches
WHERE qty > 0
AND expired_date > NOW()
ORDER BY expired_date ASC
