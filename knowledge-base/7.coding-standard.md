# CODING STANDARD

# Bakery ERP System

Version: 1.0

Status: Draft

---

# 1. General Principles

All code must follow:

* SOLID Principle
* DRY (Don't Repeat Yourself)
* KISS (Keep It Simple)
* Clean Code
* Separation of Concerns

Code must be:

* Readable
* Testable
* Maintainable
* Scalable

# 7. Controller Standard

Responsibilities:

* Receive request.
* Validate request.
* Call service.
* Return response.

Controller MUST NOT:

* Contain business logic.
* Access database directly.

Example:

Bad:

Controller → Prisma

Good:

Controller → Service → Repository

---

# 8. Service Standard

Responsibilities:

* Business logic.
* Transaction orchestration.
* Validation.

Services MUST:

* Be small.
* Have single responsibility.

Example:

InventoryService

Responsibilities:

* Validate stock.
* Apply FEFO.
* Create movement.

---

# 9. Repository Standard

Responsibilities:

* Database access only.

Repositories MUST NOT:

* Contain business rules.

Example:

Good:

findById()
findBySku()

Bad:

calculateStock()

---

# 10. DTO Standard

All requests must use DTO.

All DTO must use:

class-validator

Examples:

* IsString
* IsNumber
* IsUUID
* IsEnum

Example:

export class CreateProductDto {

@IsString()
name: string;

@IsString()
sku: string;

}

---

# 11. API Response Standard

Success:

{
"success": true,
"message": "Success",
"data": {}
}

Error:

{
"success": false,
"message": "Validation Error",
"errors": []
}

---

# 12. Error Handling

Use:

Global Exception Filter

Never:

throw generic Error()

Always:

throw BadRequestException()
throw NotFoundException()
throw ConflictException()

---

# 13. Database Rules

Never:

Update stock directly.

Always:

Use InventoryService.

---

# 14. FEFO Rules

FEFO implementation:

Service Layer only.

Never:

Inside Controller.

Never:

Inside Repository.

Algorithm:

1. Get active batch.
2. Exclude expired batch.
3. Sort by expiry ascending.
4. Consume oldest expiry first.

---

})
