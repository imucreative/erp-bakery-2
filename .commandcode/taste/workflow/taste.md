# Workflow

- Always study the project's existing knowledge-base (AI operating system, documentation index, relevant design docs) before starting work, and add a new design document when the needed design doesn't exist yet (e.g. an administrator/super-admin level design). Wants this reading rule to be an explicit, standing mandate for both feature work and bug fixing, written into the agent instruction files (AGENTS.md, rules/workflows, agent docs) so the agent always reads the knowledge-base before touching code. Confidence: 0.85
- Expects the `knowledge-base/project-context` log to be updated after every piece of work — whenever the agent fixes or generates something — as dated entries in one file per day named `knowledge-base/project-context/YYYY-MM-DD.md` ("selalu mencatat kegiatan/pekerjaan harian ... setelah menyelesaikan tugas"), and explicitly wants this kept as a standing habit, not a one-off. Confidence: 0.9
- Prefers to work through a pending/backlog list incrementally — one item at a time, finished and verified before moving to the next ("kita selesaikan 1 per 1"), rather than a single big batch of changes. Confidence: 0.6
- Wants the agent to commit finished work itself — with a clear, descriptive commit message — but only when he has explicitly told it to; work should not be committed before being instructed ("jangan langsung commit sebelum saya perintahkan"). Confidence: 0.75
