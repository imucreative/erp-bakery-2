# Workflow

- Always study the project's existing knowledge-base (AI operating system, documentation index, relevant design docs) before starting work, and add a new design document when the needed design doesn't exist yet (e.g. an administrator/super-admin level design). Wants this reading rule to be an explicit, standing mandate for both feature work and bug fixing, written into the agent instruction files (AGENTS.md, rules/workflows, agent docs) so the agent always reads the knowledge-base before touching code. Confidence: 0.85
- Expects the `knowledge-base/project-context` log to be updated after every piece of work — whenever the agent fixes or generates something — as dated entries in one file per day named `knowledge-base/project-context/YYYY-MM-DD.md` ("selalu mencatat kegiatan/pekerjaan harian ... setelah menyelesaikan tugas"), and explicitly wants this kept as a standing habit, not a one-off. Confidence: 0.9
- Before deleting any file/component/code, insists on verifying first that nothing else references or uses it ("sebelum kamu menghapus sesuatu, tolong pastikan tidak ada yang menggunakannya") — do a thorough usage/import search and report it, rather than deleting on assumption. Confidence: 0.85
- Periodically asks for a progress check and expects a compact status report that explicitly separates what is already done from what is still outstanding ("apa saja yang sudah dikerjakan & belum dikerjakan", "apa case yang belum selesai"), grounded in the actual repo state/commits. He also separates session-level progress from feature-level scope, asking "kalau fitur, apa saja yang belum selesai?" and expecting the feature backlog to be sourced from the knowledge-base status/backlog docs (PROJECT-STATUS, issue backlog) rather than only from the current session. Confidence: 0.65
- When a static enum/config list is promoted into a database reference table, expects the seed data to be added in the same change so the default values already exist up front ("kita harus menambahkan seed databasenya juga, biar default valuenya sudah terbentuk lebih dulu") — a migration that leaves the lookup table empty is incomplete. Confidence: 0.65
- Prefers to work through a pending/backlog list incrementally — one item at a time, finished and verified before moving to the next ("kita selesaikan 1 per 1"), rather than a single big batch of changes. Confidence: 0.6
- Wants the agent to commit finished work itself — with a clear, descriptive commit message — but only when he has explicitly told it to; work should not be committed before being instructed ("jangan langsung commit sebelum saya perintahkan"). Once he does say commit, he expects the agent to keep going on its own: commit, then continue straight to the next pending backlog item ("tolong commit & lanjutkan ke progress berikutnya"). Confidence: 0.8
